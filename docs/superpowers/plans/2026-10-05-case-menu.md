# Physical PC Case Menu Implementation Plan

**Goal:** An original 2016-style desktop tower in a new scene; physical Start and Settings controls with tactile audio/visual feedback; a smooth orbit/dolly into the existing Main game's monitor.

**Architecture (updated by user):** ComputerCaseMenu preloads the real Main additively before Start. Main's real monitor and world canvas are placed on the desk, with its source camera/canvas left offstage. A small explicit startup bridge reuses existing initialization methods. The same perspective camera moves continuously; no scene change, fade, screenshot or camera switch occurs on Start. Desktop input and narrative playback unlock on arrival.

**Tech Stack:** Unity 6000.4.5f1, URP 17.4, Input System 1.19, TMP/uGUI, existing licensed audio.

**Power behavior (user clarification):** Main loads in the background while the physical LCD remains black. The case power button lights the LCD backlight over .55s before/during the uninterrupted camera movement; the original live render, not a preview texture, is revealed.

## Constraints
- Preserve existing dirty gameplay edits and existing saves. Back up the live dirty Main before switching scenes.
- No added dependencies, no paid generation/API, no manual Unity YAML edits.
- Reuse native LCD mesh/materials and project CJK font/audio. Persist generated geometry as editable assets.
- Main remains the gameplay source of truth. Build list preserves existing entries.

## Review Focus
1. Repeated Start clicks must launch exactly one scene transition.
2. Settings must block case clicks and persist volume/fullscreen/reduced motion without destructive save operations.
3. Mouse, touch and keyboard navigation should work with New Input System only.
4. Main initialized after a menu load must retain all story/chat/lab systems, with no duplicate initialization.
5. Scene reload and interrupted Play must leave no duplicate camera/listener/handlers.
