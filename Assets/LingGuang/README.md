# 《灵光一闪》核心原型（按规格 v0.8 实现）

打开场景 `Assets/LingGuang/Scenes/LingGuang.unity`，点 Play 即可。场景里只有一个 `LingGuangGame` 组件，棋盘、界面、音效、后处理都在运行时生成。

## 像素神经网络表现（2026-10-02）

- 默认使用视频参考的“像素主体 + 高清柔光”：深蓝脑区轮廓、冷蓝神经元、沿轴突行进的青白脉冲；不改 `Core/` 的任何玩法规则。
- `PixelBoardPresentation` 用独立世界相机绘制低分辨率 HDR 纹理，在 HUD 下方合成清晰像素和连续光晕。1080p 时世界纹理为 640×360；窗口变化会自适应重建，禁用或退出时释放。主相机不绑定纹理，因此原有鼠标拾取、拖拽和缩放坐标保持不变。
- 界面文字和按钮维持原生分辨率；候选卡图标使用独立像素采样。现有神经元 PNG 和六方向朝向不变，以材质转换冷色，而不是覆盖原图。
- 普通状态弱化格线；进入放置预览时显示可用网格。默认镜头显示整个脑区，仍可滚轮缩放、拖拽平移和双击复位。
- F2 的“降低闪烁”同时降低脉冲强度和新合成器的光晕强度。
- 不安装 Pixel Perfect Camera 包，不改 URP 资源或项目全局抗锯齿选项。这里是像素主体与高清 UI 混合风格，而不是固定视口、黑边式的严格像素整数缩放。
- 运行时合成成本为 O(屏幕像素数)，世界纹理空间为 O(低分辨率像素数)；稳定尺寸时复用纹理。连锁脉冲沿池化渲染器播放，每帧最多创建 48 条脉冲请求。
- 测试与运行截图保存在工程 `Evidence/PixelStyle/`；目标验证环境为 Unity 6000.4.5f1 / URP 17.4 / macOS Metal，其他图形后端和独立构建未验证。

## 目录

- `Core/`：纯 C# 规则层（asmdef 设置了 `noEngineReferences`，不引用 UnityEngine）。
  - `GameConfig.cs`：所有数值。运行时从 `Assets/StreamingAssets/LingGuang/GameConfig.json` 读取，文件不存在时自动生成；改完保存会自动热重载（F5 强制重载）。棋盘地图 `mapRows` 也在这里，改形状需要新开一局。
  - `HexBoard.cs`：odd-r 六角格、方向、距离、沟（中线、外侧沟、次级沟）、窄桥、连通检查。
  - `Simulator.cs`：一次确认 = 一次连锁，按第 5 节流程逐拍输出 `SimEvent` 列表。
  - `Mods.cs` + `Effects.cs`：物件、药品、关口统一的数据驱动效果系统（触发时机 + 条件 + 操作 + 数值）。
  - `RunState.cs` / `RunFlow.cs`：一局的全部状态与流程（放置、旋转、移动、商店、用药、确认、结算、废退、修剪、记忆折叠、沉淀、无依、本能、老年、流光、领悟）。
  - `EndingNamer.cs`：第 13 节终局命名（底色三轴、连接、方式、纹理、性格）。
  - `Bot.cs`：贪心机器人，只用于平衡测试与自动演示，不参与游戏。
- `Game/`：表现层，只读事件流播放，不做规则判断。
- `Tests/Editor/SimulatorTests.cs`：第 11 节验收用例 T01–T22 + 整局冒烟测试（EditMode，Test Runner 里运行 `LingGuang.Tests`）。

## 规格里不明确、我做了取舍的地方

- 电量流失：只对“本次连锁中收到过电”且电量为正的灵光扣，最低 0；负电量不动。
- 导通计数：只统计“本拍向它投递、并且在它闪之前送到”的光丝；同拍闪过后再到的 0 延迟投递不计导通，电量留到下一拍。
- 涟漪：每个 Conduct 产生一个涟漪（同一灵光被两条光丝点亮会产生两个，会合并成数量 2 的群）。被涟漪或微弱连接推到阈值、且本拍没有光丝投递的灵光，算“涟漪导通”。
- 汇聚的“不同来源”：按投递来源灵光（记忆算一个来源）计数，灯塔也算一个来源。
- 灯塔覆盖用“不穿沟的路径距离”。
- 记忆折叠允许本能灵光成为成员（否则婴儿期几乎无法折叠，老年灯塔也就没有可照的记忆）；记忆成员可以旋转（消耗可塑度），不能移动。记忆“每被触发一次 −1”按每次触发计算。
- 无依：从放下那一轮起算 3 轮扎根期，之后每轮结算检查，连续 2 轮无依就漂走。
- 拾物点格子不能放灵光；物件槽满时拾取改为 +2 余光。
- 退烧贴：本轮已闪过的灵光再次闪时不计光量、也不抬阈值。
- 短视频的“新鲜度惩罚永久 +1 档”只在已经出现重复（k>0）时叠加。
- 分离关口按规格“首次到达童年后才出现”，用 PlayerPrefs 记录。
- 领悟（第 14 节）只做了简化版：未花掉的领悟在下一次结算时自动精进到本轮出现最多的回路型，每 3 点升 1 级（每级光量 +25%、倍率 +0.5，可在配置里改）；顿悟卡、眼界、领悟柜需要设计决策记录里的卡表，未做。
- 商店按第 9 节的简易版（物件 5、药品 3，每轮 2 物件 + 1 药品），另加了第 14 节的“刷新 2 余光，每刷一次 +1”。

## 规则审查后修掉的问题

用独立审查把 Core 与规格逐条对过一遍，修了：
- 外侧沟缺口坐标写错（左侧颞区被整片封死，导致每局的随机次级沟都生成失败）。`GameConfig.json` 已按新默认值重新生成；如果你手上有旧的 JSON，请删掉让它重新生成。
- 退烧贴会让互指的光丝无限回荡直到 200 拍上限，还白送“长链”。现在仍然抬阈值，只是不计光量；连锁被安全上限中止时不识别回路型。
- 灯塔的电不再落到本次的起点上（起点本来就直接闪）。
- 陈光区域被触发的轮次可塑度 −1；移动到固化的陈光区域会被拒绝。
- 老年的光丝延迟 +1 不影响记忆；微弱连接按“每对每拍一次”去重；W（单拍最多闪光数）开始统计；分离关口在到达童年时就解锁；“？”关口下药品不能把起点次数加到 1 以上；安全上限正好 200 拍。

## 平衡观察（贪心机器人，种子 1–6）

婴儿到青春期普遍超出目标 3–15 倍；成年第 1 轮经常断崖（灯塔缩到只照锚点、本能光量衰减、新鲜度开始惩罚），6 局里 1 局打到老年关口（9435/10000），其余倒在成年或中年。真人不会逐格穷举，前期会比机器人难，后期断崖会更明显。目标分、灯塔半径、本能衰减、领悟等级加成都在配置里，建议试玩后再调。可以在 Unity 里用 `LingGuang.Core.Bot.PlayRuns(cfg, seeds)` 批量跑。

## 水波涟漪（2026-10-02，替代点阵扫光）

`NeuralWaveField` 将真实 Fire 事件送入 `WaterRipple.hlsl`，生成衰减的径向正弦波列。多个源的带符号高度和坡度先相加，再计算连续波面明暗，表现为圆形水纹扩散与交叠，不再绘制点阵或扫光。仅把 0.24 秒内、距离不超过 0.8 世界单位的近邻触发合并；远处触发保持独立，最多 8 波、每波 4.2 秒。只是表现，不改变传导、计分、格子与物理位置。

像素合成器用同一波面坡度做轻微折射，位移小于 0.032 世界单位（六边格半径 0.62）；输入相机与坐标不改，HUD 不参与折射。F2 降低波面明暗并禁用折射，无活动波源时也关闭折射计算。波面限于原双脑区域。清理特效/新局清空波源，销毁时释放专有材质。寿命、速度、频率、波包宽度由 C# 上传，两 shader 共享计算文件；改容量仍须同步数组长度。

验证与录像见工程根目录 `Evidence/WaterRipple/README.md`。这是解析水波近似，不是流体求解或边界反射模拟。CPU 时间/空间 O(W)，shader 时间 O(P×W)，W=8；P 包括低分辨率波面与原生分辨率折射区域。未做跨平台 GPU 性能基准。

## Feel 光电反馈（2026-10-02）

使用工程现有 Feel 6.1。`FxPlayer` 的 Fire、Transmit、PatternRecognized 接入 `FeelElectricFeedback`；节点短促辉光由原生 `MMF_SpriteRenderer`、`MMF_Scale`、`MMF_Particles` 播放，沿真实连线行进的电弧由自定义 `MMF_NeuralElectricArc : MMF_Feedback` 播放。不是只引用插件但另写一套播放系统。MMF_Player 在本工程实际属于 `MoreMountains.Tools` assembly，因此仅增加项目 asmdef 引用，没有修改插件源码。

- 保留像素棋盘、高清 HUD 与水波涟漪；只缩放装饰节点，不改规则或拾取坐标，不增加全屏闪白。
- 固定预分配 12 个点亮槽、24 个电弧槽，共 36 个 MMF_Player；超出同帧限额丢弃装饰反馈，跨帧轮转复用，可能提前截断旧尾迹，不影响真实传导。
- 电弧固定 20 段，不每帧随机抖动；所有效果复用 Gfx.Additive 材质。普通节点最多发射 4 个短粒子，快进 2 个，降低闪烁模式禁用粒子并降低亮度、取消电弧锯齿。
- F2 沿用现有 reduceFlash 状态；切换时立即清掉旧高亮。快进缩短装饰包络和尾迹，不修改全局 Time.timeScale。新局、跳过和停用时停止 Feel 播放并清理尾迹。
- 该效果层每帧 CPU 时间 O(I + A×S)，空间 O(I + A×S)，I≤12、A≤24、S=21；粒子容量每槽 12。GPU 成本还受辉光覆盖与叠加影响，未做性能基准或独立 Player 构建。

64/64 EditMode 测试通过，另有真实连锁播放、原生反馈活动及同帧 100 次触发限流验证。录像与证据位于工程根目录 `Evidence/FeelElectric/`。

## 无限回荡（2026-10-02 晚，偏离规格 v0.8）

规格里每闪一次阈值 +2、没有上限，所以任何回路都会衰减，无限回荡不可能出现。现在加了三条规则，都在配置里，可随时改回规格原样：

- `refireRaiseCap = 6`：一轮内疲劳抬升最多 +6（内部单位）。`-1` = 规格原样（无上限）。
- `carryOverFire = true`：本拍已经闪过、但电量仍 ≥ 阈值的灵光，下一拍再闪。否则 0 延迟的髓鞘化回路会卡在同一拍里停掉，光丝越强越不能回荡。
- `infiniteEnabled = true`：每拍结束时比较整条连锁的状态（电量、疲劳、扰动、光丝等级、待处理投递）。状态重复，就判定为无限回荡：立即结束连锁，按 `infiniteCredits = 6` 圈记光量（倍率不按圈累计），并识别为最高级回路型“无限回荡”（光量 100、倍率 6）。画面上出现“无限回荡 ∞”横幅。

能形成无限回荡的结构：每个灵光要同时收到两路以上的电，比如三个两两相邻的本能灵光。单入口的环（传导首尾相接）怎么加粗都不够。

调参用的无头运行器在 `Tools/LingGuangSim`（`dotnet run -c Release -- --cap 8 1 2 3`），单元测试可用 `Tools/LingGuangSim.Tests`（`dotnet test`）在 Unity 外跑。

## A01 传导本体（2026-10-02，采用用户 HTML 小样）

只替换 `Shape.Conduct` 的棋盘本体、放置预览与候选栏图标。其他形态、玩法规则、Feel 连锁光电、水波和输入相机保持原实现。参考原件副本位于 `Evidence/A01Conduct/reference/index.html`；该 HTML 的预览侧栏、示波器和等高线背景不是本次游戏界面改动。

- `ConductA01Geometry` 移植小样 seed=7 的 mulberry32 和分枝算法，细长菱形（0.42）、双层膜（内层 0.72）、轴丘缺口（0.22）、单轴突及末端分叉、后侧树突和晶体切面。几何单位严格采用 HTML 实际代码的 S=格子外接半径×0.6；轴突为 0.75S，并非把界面“0.75 格”的文字直接当世界距离。

- 保留像素世界，因此极细线在低分辨率缓冲中做最小覆盖抗锯齿；不是浏览器原生分辨率的逐像素复刻。呼吸只改变亮度，不缩放本体。F2 降低呼吸幅度到 ±2.5%，关闭微闪和扫描，弱化流动光点。禁用和放置预览不播放扫描/微闪。
- 两个绘制组件/本体，所有节点共享线网格、材质；用 MaterialPropertyBlock 更新状态，不克隆节点材质。每节点每帧 CPU O(1)，静态几何内存 O(E)，节点状态 O(N)，GPU 约 O(N×E + 覆盖像素)，E 为固定线段数。HUD 图标首次栅格化 O(R²E)，缓存后 O(1)。未做 Player 构建或 GPU 性能基准。

证据：`Evidence/A01Conduct/README.md`。71 项 EditMode 测试通过；几何端点与实际执行 HTML build() 的结果比对，运行验证包含完整扫描周期、微闪、流动点、降低闪烁、42 格拾取往返及 Feel/水波共存。
