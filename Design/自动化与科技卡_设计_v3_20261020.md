## 1. 科技卡统一写法

名称沿用正在整理的技能书命名，本稿不抢改名称。栏目标题用「训练」「识图与语言」「数据」「自动作答」「显示与操作」。不再使用「脑型」。需要描述切换时写「更换模型」，需要说明技术时写「模型结构」。

每卡只保留：**名称 / 能力方向 / 具体效果**。能力方向建议 4–8 字，具体效果建议 14 字以内；不以删掉关键限定词换取字数合格。购买状态另占一行，价格由游戏计算，不照抄稿中的 ¥30、¥38。

示例：

> 学习率搜索　　　　　　　LRS
> 调整学习步幅
> 显示六档学习率
> 购买 ¥150

> 迁移学习　　　　　　　　TL
> 复用学习成果
> 更换模型保留部分成果
> 购买 ¥{实际价格}

「更准」只用于实际提高正确率的机制。「稳定」要点明对象：参数更新、成绩波动或运行状态，不能一词包办。不要使用“不掉、不卡住、不崩、不断档、练坏、换脑型”等表达；也不保证购买后每题正确、每轮涨分或永不中断。

### 标签与年份

用户已确认「就是v2里UI表现的」，以下标签格式已确认：

- 技术：灰字 `缩写 · 年份`，名字中不重复塞英文和年份。
- 工具类：只显示通用缩写，如 `LRS`、`CKPT`、`AUG`；删除「工具2016」。没有通用缩写时不造缩写。
- 游戏内未公开的探索：`自研 · 2016`，不把 2017 年论文写成 2016 年既成事实。
- 年份指具体技术版本或指定论文，不默认是“发明年份”。LeNet 的 1989 与 LeNet-5 的 1998 必须先选定具体指代；不能因为排版示例直接改成 1998。RNN/MLP 等历史版本同理。
- 标签是元信息。缩写可点开现有图鉴的科普条目；年份不再额外复制成一排按钮。维持已确认的“无详情按钮，图标点击或悬浮看说明”。

### 弹窗：先结果，后知识

顺序：名称与灰标签 → 能力方向 → 具体效果 → 一句说明 → 未满足的条件 → 价格。

- 正文一句，目标 20 字，最多两行；条件属于购买信息，不能截断或藏掉。
- 已满足条件折叠，仅显示未满足条件；具体对话解锁原句必须完整展示。
- 术语标签进入现有图鉴，返回保留科技树位置。科普最多三句，不增加「看详细科普」按钮。
- 维持本轮已修好的即时悬浮、点图标固定说明、价格购买、窄窗可滚动。不强制“一屏无滚动”导致购买条件再次裁切。
- 英文同步采用相同含义，不硬套中文字数。例：`复用学习成果 / Reuse learned progress`；`平缓参数更新 / Gradual parameter updates`；`扩大复核容量 / Expand review capacity`。

## 2. 任务提醒

开局不生成任务，也不弹「暂无任务」。玩家主动打开空任务列表才显示「暂无任务」。这不取消开局答题剧情及既有引导。

新增或更新任务时，游戏内右下角出现一张 300×96 提示卡，240ms 淡入，停留4秒淡出。显示「新任务」或「任务更新」、任务名、一句正文、一个「查看」按钮；不填尚未确认的价格。

任务图标采用 Windows 式柔和亮暗变化：一轮1.6秒，前3轮较明显，之后低亮度呼吸。点击任务图标或「查看」即停止并打开对应任务；关闭提示卡也视作已看到，停止闪烁，任务未完成标记仍保留。

本稿将用户的「点击暂停」解释为**停止提醒闪烁**，不是暂停整个游戏。挂机暂停另设独立按钮，不能混用。

更新合并：同任务2秒内更新合为一条；多任务同时出现显示「{数量}项任务有更新」。数字进度每次变化不弹窗，只在新目标、完成、需要操作时提醒。升阶演出、开机、选档期间排队，退出演出后合并展示。

减少特效：仅静态提示卡与小圆点；提示音单独控制。提醒只在游戏窗口或玩家主动开启的挂机小窗中，不调用 Windows 系统通知。

示例：

| 标题 | 一句正文 | 按钮 |
|---|---|---|
| 开始自动作答 | 前往科技树查看自动作答。 | 查看科技 |
| 后台作答已开启 | 查看正在处理的题目。 | 查看后台 |
| 待复核题已满 | 处理待复核题后继续作答。 | 去复核 |
| 数据包已下载 | 拖入练页安装区即可使用。 | 打开资料 |

首次60%检查点是否提前触发自动化，以及新线程机制，仍属玩法变更，待确认，不随文案修改静默落地。

## 3. 挂机小窗：一眼看懂它在做什么

名称用「挂机小窗」，不叫「离线小窗」。**窗口仍运行属于在线挂机；真正退出后没有实时界面，只在下次启动结算。** 不暗示退出后模型仍在电脑上运行。

### 外观与内容

- Windows桌面右下角，宽360、高212（DPI逻辑尺寸）；距工作区右下边16，避开任务栏。最小宽320。
- 深石墨色实底、1px低亮描边、12px圆角，沿用游戏已有字体。无实时模糊、无新字体资源。
- 顶栏：状态点、`{AI名字} · 挂机中`、恢复主窗口、更多。置顶默认关闭，可主动开启；不自动抢焦点。
- 主数值：`本次挂机收入 ¥{累计}`，以已结算金额为准。
- 次数值：`近10秒平均 ¥{速率}/秒`。无足够数据写「统计中」，不借演示数字冒充真实收益。
- 中部：当前题桌、实际完成量或下一题进度、复核 `14 / 20`。只有多任务机制确认后才显示并行槽数。
- 底部：`暂停挂机`、`返回游戏`。暂停后文案变「继续挂机」；金额停增，状态变「已暂停」。

可拖顶栏，位置按显示器工作区记忆；屏幕变化时自动回到可见位置。进入小窗前保存正常窗口尺寸、位置与全屏状态；恢复时原样返回。第一次开启显示简短提示「游戏仍在运行」。

### 动效

| 事件 | 表现 |
|---|---|
| 实际结算 | 金额在180ms内过渡到新值；同一秒到账合并一次 |
| 新增收入 | 仅数字右侧出现一枚小额 `+¥`，向上8px淡出，最长450ms |
| 正在答题 | 一条细进度线，按实际作答间隔推进，结算时轻亮 |
| 连对升档 | 状态标签描边亮一次；不抖整个Windows窗口 |
| 需人工处理 | 琥珀色状态点，显示具体原因和可点击操作 |
| 用户暂停 | 进度冻结，保留累计，不伪装离线收益 |
| 离线收益到账 | 下次进入游戏仅一次结算卡，不在小窗中重复累计 |

小窗默认30fps；无到账时不刷新金额文字。减少特效关闭飘字、呼吸和进位动画，数字直接更新。默认静音，不按每千元重复响铃。

### 入口和操作

设置 → 显示：全屏 / 窗口；已解锁自动作答后，后台面板增加「挂机小窗」。不要因为 Alt+Tab 自动弹出置顶小窗。

小窗更多菜单：置顶开关、退出游戏。关闭小窗默认恢复主窗口，退出游戏必须使用明确的退出操作并保存。任务栏仍能找回游戏；第一版不依赖系统托盘隐藏进程。

小窗是同一游戏进程的显示模式，不启动第二个 Unity 或第二个大模型；页面隐藏后停止其绘制，后台只保留必要结算。小窗不因主界面隐藏而把挂机误判成暂停；用户明确暂停、游戏内断电、复核满时按规则停止。

## 4. 离线收益选项

建议设置文案：

> 离线收益　[开关]
> 退出游戏后，下次启动补算挂机收入。
> 按50%效率，最多8小时。仅增加游戏资金。

50%／8小时与默认开关均是附件的新提议，已向用户询问，未确认前不改经济系统。原型仅提供外观演示。

结算设计：保存已解锁且未暂停的后台状态、有效速率、UTC时间与结算标识；退出后不运行AI。没有合格模型、断电、复核满、手动暂停时不得假定仍有收益。不补训练样本、不自动通关、不推进需玩家点击的剧情。

每个存档独立登记已结算时间，重复读档不能重复领取；崩溃恢复与自动档也走同一登记。回拨时间收益为0，但不要把领取水位向后移；向前调时钟仍可能在纯离线游戏作弊，不能声称仅用UTC或8小时封顶就完全防住。离线收益和在线累计不能双算。
