- 关机状态：`unpinned` / `stop` / `no_stop`；保留旧 E1/E2/E3 字段原义。
- 公开产物 `artifactId` 仅在虚拟发布实际成功后存在；R4 不产生公开产物。游戏操作不连接真实发布服务。
- 尾声显示日期默认 `20170613`，史实头条明确论文 v1 发布于 `20170612`。显示日期与模拟经济时钟分开，不补算数月房租或训练。

- 正式通关之前必须有真实前置通过、路线落定和相应发布回执；开发预览可以单独验证展示，不用测试状态开放正式入口。

## E-B 纯内容契约

资源分类修订（root确认）：两份新终局内容资源统一放 `Resources/LingGuangV05/Epilogue/`，即 `ending_public_discourse.json` 与 `ending_letters.json`；加载键分别为 `LingGuangV05/Epilogue/ending_public_discourse`、`LingGuangV05/Epilogue/ending_letters`。原文的 `Story/` 路径建议被此修订替代。`Story/` 保持严格剧情beat验证，不让内容目录被当成剧情脚本。本项仅改变资源分类，不改变功能。

命名空间 `LingGuangV05.XingGuang`，新 `XgPublicDiscourseCatalog`。内容记录最少含 `id, stage, since, platform, route, requiresArtifact, sourceIds, titleZh, titleEn, bodyZh, bodyEn`。平台用 `news/forum/site/miaoyu/yy`。日期使用 YYYYMMDD 整数。

筛选上下文 `XgPublicDiscourseContext` 只含公开选择值：当前能力阶段、公开新闻日期、目标平台、已安装平台、发布路线与公开产物 ID。能力阶段只控制玩家看到哪些内容，不能让角色据此声称知道私人进度。日期和阶段双重检查。R4 内容不可揭露“玩家没有发布”。

协调者追加：上下文允许 `publicEventIds`（显式公开事件 ID 白名单）。使用体验、下载或衍生发布等具体主张必须另外满足对应公开事件回执；不得从路线或产物 ID 推导事件发生。E-B 资源逐条列 `requiredPublicEventIds`；E-A 仅在游戏内发布实际成功、相应虚构公共事件落实并保存回执后提供这些 ID。这不是现实用户遥测。无证据时隐藏相关内容，不隐藏独立史实或原创泛论。

内容目录返回记录，不自动发玩家帖子、添加好友、完成引流或更新私聊。投递去重和主动提示冷却在接入层持久化；旧档补内容只供主动回看，不批量弹提醒。为避免错过验收，目录检查与实际平台显示分别记录。

## E-C 展示契约

目录 `EndingLetterCatalog`，新资源 `Story/ending_letters.json`；三信都带来源 `public_article`，不冒充私人寄送。展示组件输入已选文章、语言、阅读位置，以及以下回调：

- `RequestSaveArticle(articleId)`：只由玩家明确点击发起；未持久保存成功不亮邮箱红点。
- `RequestOpen(articleId)`：展示告知与“先读信 / 暂不打开”；不通关。
- `ReadingPositionChanged(articleId, paragraphId)`：可恢复阅读；关闭/最小化不完成。
- `RequestComplete(articleId)`：仅最终“读完，保存并返回标题”按钮发起；等待 owner 回报成功/失败；失败留在原页可重试。
- `RequestBackToDesktop()`：中途退出安全。

展示层不自行订阅真实邮箱、不生成私人事实、不关闭全局模型服务。错误提示必须明确“尚未通关”。重放是只读模式，不能再次发完成/奖励请求。

## 统一保存规则

继续复用 `AtomicSaveStore.TrySaveSnapshot`，不新增独立磁盘格式。完成候选含路线、决策方式、关机状态、文章版本、完成回执；保存成功后才能发标题路由/成就事件。失败恢复内存状态，保留上一份可读存档；重复按钮、迟到回调、读中重启均须验收。旧已通关档不倒退，旧 ID 不映射成新发布路线。

## 验证与缺项

root 单实例、低优先级运行 Unity。其他 agent 只写源码/数据、静态检查和候选测试。策划来源与新增对白清单交付后才将对应条目标为已移交；编译通过、核心检查、真实界面交互、自然完整通关分别记证据。红队三关、记忆卡或上线夜若未完成，继续列为缺项，不用演出成功替代。
