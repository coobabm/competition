## 2. 体验主线：屏幕外的普通人

从“电脑能下棋吗”走向“出错以后谁接电话”。六阶段中，普通网友不是来替作者讲道理：有人省下打字工夫，有人担心排班，有人想查来源，有人只想下一盘棋。相同虚构网名跨阶段再出现，观点会因公开事件变化，但不会因为玩家的隐藏训练变化。三结局都既有受益者，也有负担；不设善恶分数、万人欢呼或世界末日。

主角2016年已上班两年、独居；舞台始终是房间里的虚拟桌面。群友可以说自己明天上班、翻译兼职或买卖旧卡，不能无证据说主角刚交房租、升级设备、熬夜训练。2017尾声只有新公开新闻、虚构公众体验及已披露内容；不把2023年的专有名词和争议伪装成2016帖子。

固定原创网名建议：纸飞机（译文校对）、晚班车（上班族）、旧散热器（硬件爱好者）、半页纸（小站维护者）、路边棋盘（棋友）。接已有群昵称前先验证同名人物是否存在及是否群成员；否则作为论坛新用户，不能强插YY群。

## 3. 信息从哪里来：可实现的知情与公开边界

每条内容有三层：`historicalFact`（公开史实）、`fictionalPublicEvent`（游戏内公开产品/网站反馈）、`personalDisclosure`（角色确实接收的玩家陈述）。后台 stage 只选投放队列，不变成角色句子。

| 想说的内容 | 必须已有证据 | 没有证据的替代 |
| --- | --- | --- |
| “我用了那个站” | 公开服务已提交成功，角色有使用事件 | 泛论同类服务，不声称亲测 |
| “这是你的网站” | 玩家主动发布/分享，角色已读，身份绑定成立 | “有人贴了一个站”，不点玩家 |
| “你决定暂时留下” | 玩家实际发送此陈述，老周接收并记录 | 公开文章谈延后发布，不说“你决定” |
| “你给它留了开关” | 玩家主动披露该规则，非只看 route | 删除该句，不从规则槽偷看 |
| “它回了什么” | 玩家主动选择发送回答，并能预览原文 | 保留“如果愿意可以说说”，不自动转发 |
| “你帖里写过……” | postPublished + readReceipt + authorLinked，且引用内容在帖中 | 泛论，不引用本地草稿、私人日志 |

公开评论默认谈产品化名，不把化名等同主角YY。R1 的上线界面确认“发布服务页，提供在线访问”；R2 确认“发布模型下载页及说明”；两者都把将公开的字段逐项预览：产品名、简介、能力/限制、维护或许可说明。玩家姓名、YY、邮箱、聊天、记忆卡原文、硬件清单默认不公开。发布成功写稳定 artifactId；失败保持待重试，不产出虚假社会反应。R4 的“保留在本机”不产生公开帖。

不强制玩家做网站经营支线、付¥2,000或买爬虫才能看到尾声。R1/R2 使用终局独立发布页作为交付入口；若拥有网站，玩家可选择镜像到自己的站，但不是默认额外披露。原网站收益/主动贴吧引流/阶段3起开放全部保持。

### 3.1 无YY、无邮箱地址，老周的信怎样成立

默认 A：老周有**对所有人可见、同一天写成的三封公开主题信**，标题分别“开着的门”“离开手的副本”“还没有按下的按钮”。主题选择由玩家本机尾声呈现，不让老周在后台按未知选择写私人信。三封都可在公开专栏看见，完成后均可在资料页阅读；当前路线只决定先推荐哪一封。

每条尾声页末尾常驻非强弹窗入口：“老周更新了公开来信：三种做法，三封信。”玩家点 **“保存本篇到游戏邮箱”**，先说明“将公开文章保存为本地邮件，不发送地址，也不会告诉作者你选了什么”。点击后写 deliverySource=public_saved、sourceArticleId、savedAt；下一拍才亮邮箱红点。这样即使从未加YY、不认识老周、从未发帖也成立；发件人显示“老周 · 公开来信（本地保存）”，不是“老周刚寄给你”。玩家不点保存就保留入口和“继续尾声”按钮，不自动订阅、不阻塞返回桌面；继续通关时明确执行同一保存操作。

已有贴吧联系也只提供相同公开入口；已有YY联系人可发“我把关于发布的几封旧想法整理到专栏了。”前提是本人有一次固定发表公告，非私人判断。可以有已披露后由玩家请求“把这封回信保存到游戏邮箱”的私人变体，但仍是站内信转存，无需邮箱地址；作者身份可来自已存在的贴吧联系。不得在保存时自动加YY。现实网络不参与，游戏也不读取真实邮箱。

私人段落仅在角色看过明确披露后插入：附录列可用插句及证据键。公开信主体绝不读隐私。用户不分享时仍能完整体验三结局；读信不是奖励披露秘密的门槛。

## 4. 六阶段投放、平台职责与节奏

六阶段都覆盖摆渡讨论、贴吧论坛、网站、喵鱼、YY五种表达，详细30格双语稿在配套清单。平台未安装/网页未解锁时不弹假窗口、不提前安装：先在已可达摆渡看到公共话题，待平台真的可用显示相应存档卡。自营网站阶段1–2不开放经营，新内容只在公共主题站；阶段3之后有站的玩家才看经营反馈，未建站者看别人的公开站，且没有资金收益。

每阶段至少有一条可达的完整主题链，并为五平台各备一项；不能因为玩家没装喵鱼就声称已看过喵鱼对白。内容仅作氛围，不加任务、经验、钱、训练样本、人格分或升阶条件。

触发算法（明确 A 数值，属于文案调度新配置）：首次进入阶段后累计60秒前台安全时间可入队；一般公共话题卡相隔至少180秒前台时间，同平台至少300秒，主动新消息每10分钟最多2次，全局同一主题新红点只一次。玩家主动翻旧帖不受冷却。考试、剧情、钉卡、拖动窗口、账单警报、正在输入、重要来信与终局动画期间暂停队列；重要事件后等30秒且输入框失焦才投放。沿用现有更严格的避让，不建立另一套抢先弹窗系统。

每项`earliestDate`与stage门同时成立才进入“新鲜内容”队列。玩家太快到阶段5但日期尚早：只用原创泛论，不显示尚未公开的GNMT新闻；后来日期到了再出现档案卡。玩家跨过多个阶段：已错过内容进入“往期讨论”，不补发30条消息，不伪造已读。每阶段最多一个主动提示，其余平台在主动打开时显示；各平台不得同秒齐刷刷响应玩家。

网站经营：只有真实发布文章、访客已读才生成针对该文评论；查看公开案例可以随时，但不算经营/引流。评论不自动发布玩家立场。喵鱼条目不因点开而下单、替玩家卖卡或泄漏设备。YY群只谈公开新闻，老周私聊保持主动加YY门。

## 6. 三个公共结局：可见范围、演出和余味

### R1 上线运营｜《开着的门》

公开条件：服务成功发布，可访问页说明能力与限制；匿名公开入口不自动和玩家身份绑定。公众只评价其实际收到的答复与运行状态。亲友仅在确实用过或看到公开链接后才谈这个具体服务；否则YY用同类服务泛论。不能由一晚的日志宣布全城失业。

视觉母题是一盏留着的窗口灯：访问状态、排队点、手工更正日志。正面是陌生人真的完成了小事；代价是后来要有人解释、修正、响应投诉。界面保留“一次未解决的留言”，不倒逼玩家额外经营；可阅读，无新任务。

公开文章：小站帮助整理商品说明；评论要求把不确定写清楚。论坛串：用户感谢节省时间；另一人问错误找谁；维护者公告修订入口。YY两句只谈公开站点体验，不喊玩家“作者”。完整双语例见R1-N/F/Y/W/M。若没有公开身份绑定，老周信只讲持续维护；有披露才追加收到消息的私人段，不泄露关机规则。

### R2 公开模型｜《离开手的副本》

公开条件：模型包发布成功，说明页包括版本、文件校验、能做/不能做、许可及不含个人聊天的声明。公开可下载不保证真的有人fork；本稿虚构衍生项目只有在带时间的“下载/发布新副本”事件发生后显示。来源许可未确定不能声称“一切都可商用”。实施者须把许可选择与现有资产实际权限一致。

视觉母题是同名文件长出不同后缀：原始包、修订包、改名包。一个改进者愿意把修正送回来，一个版本隐藏来处，另一个读者找不到究竟谁负责。不是“公开必然坏”；也不把所有衍生作品归玩家所有。关机只影响玩家持有的实例，不控制下载出去的副本。

论坛串围绕“哪里能复现、哪个版本改过、出错找谁”；YY泛论“可下载”和“能在普通电脑上跑”的区别。商业与开放都有合理意见。老周信写不再是唯一作者后的边界；无披露时不能说“我下载了你的模型”。完整双语例见R2-N/F/Y/W/M。

### R4 暂不发布｜《还没有按下的按钮》

公开条件：无。保留本地不生成公开帖子、取消公告或“神秘开发者没有发布”的热搜。真实Transformer头条照常发生，网络讨论其他已公开系统及假设性的延后发布。玩家能看见世界在继续，但不能让世界知道自己按过哪个按钮。

视觉母题是窗外早班与本地文件夹：没有新增公众访客数字；网站经营若原本存在，保留其已公开文章的普通维护活动，不突然出现模型下载入口。喵鱼仍有人买显卡，YY仍有人早起上班。提供“本机备忘”显示玩家真实路线，是只给玩家看的界面，明确“仅自己可见”。

公开论坛三人争论先测、先用、谁负担等待；没有人评论玩家的沉默。若玩家自愿发表“暂不发布说明”，则公开串改用已发布文本回应，依然不猜具体能力/训练数据。老周信是一封写给“还在考虑的人”的公开文章，不是神秘人洞悉选择。完整双语例见R4-N/F/Y/W/M。

三路线共同的2017头条完全一致。分支差异属于**游戏内的社会后果/玩家所看到的公共讨论**；不改变史实。若发布结果尚未真正执行，不得只靠选项枚举生成后果；若缺三关/固定三格等先决机制，演出可在开发预览中验证，但不开放正式通关入口冒充闭环。

## 7. 邮箱红点、确认、读完与回标题

初始邮件行与鼠标悬停固定说明：

> 终局来信。双击前请注意：阅读后点击“读完，保存并返回标题”将完成本结局。你可以先阅读、随时返回桌面。打开信件本身不会通关。
>
> Ending letter. After reading, choose “Finish reading, save and return to title” to complete this ending. You may read first and return to the desktop at any time. Opening the letter does not complete the game.

首次双击（或键盘选中后Enter、触屏明确打开按钮）弹小确认，不把敏感动作绑定双击本身。标题“打开终局来信？” / “Open the ending letter?”；正文“读完并确认后，本结局会保存为已通关，并返回标题。现在只打开信件；你仍可中途退出。” / “Once you finish and confirm, this ending will be saved as completed and the game will return to the title screen. This action only opens the letter; you may leave while reading.” 按钮 **先读信 / Read first**、**暂不打开 / Not now**。默认焦点“暂不打开”；确认后同一封不反复弹，存档记 consentShown；新的路线/新的槽位需独立确认。

阅读时正文可滚动、字号可调，不按滚动到底自动完成，不要求停留秒数。页尾唯一最终按钮 **“读完，保存并返回标题” / “Finish reading, save and return to title”**；旁边始终有“先回桌面，稍后继续 / Back to desktop; continue later”。底部按钮可用不代表系统推断阅读理解。读中关闭、Esc、最小化、切语言、断电、退出游戏都不通关；保存页码/相对滚动位置，重开继续。红点表示未打开，已打开未完成改空心小标“未读完 / Unfinished”，不能靠红点消失认定完成。

最终按钮走事务：冻结重复点击 → 生成待保存状态（completionReceipt、路线、决策方式、关机状态、公开证据快照、letterVersion、已读完）→ 原子保存成功 → 标记chapterComplete/图鉴一次 → 过场 → 标题。保存失败保留信和按钮，提示“没有保存成功，尚未通关。请重试。” / “Saving failed. This ending is not complete yet. Please retry.”；不丢信、不跳标题。优先使用现有SaveStore原子写能力；若没有，协调者补临时文件+原子替换与备份，不能由三agent各做一套。

标题“继续”若该槽已完成，默认打开“结局档案”并提供“从选择前继续”的独立分支副本，不覆盖已完成槽。读信前自动保存可恢复的选择前检查点，但不把私人训练/聊天复制进公开发布包。回看不扣费、不重发邮件、不重复成就、不重做公开动作，结尾按钮改“返回结局档案 / Return to endings”。只有实际完成的路线点亮通关记录；公开三信都可读，不等于三路线均通关。

旧档策略：

| 档案情况 | 处理 |
| --- | --- |
| 旧ending=E1/E2/E3-*且chapterComplete=true | 保持完成；保留旧结局编号/回看；新route=Unknown，绝不猜发布方式。可从新章节检查点另走三路线，不追缴邮件 |
| 旧已选E*但chapterComplete=false（异常/中间档） | 保护旧字段，进入旧结局恢复或选择前副本；不自动映射R1/R2/R4 |
| 新routeCommitted=true、mail未保存 | 直接恢复F7，公开来信入口仍可达，避免动画重复和软件安装软锁 |
| 已保存来信未打开/读中 | 恢复F8/F9及阅读位置，不再跑几个月经济 |
| completionReceipt已落盘但跳标题前崩溃 | 下次进入标题/结局档案，无二次奖励 |
| 保存失败 | 留在信页，完成标记不外泄；旧成功档可恢复 |
| 早期内容补丁装入后期档 | 往期讨论可读，无批量新消息、不造日期/已读/网站访问 |

## 8. 资产、音效、无障碍与性能

复用虚拟桌面、浏览器排版、贴吧气泡、YY、邮箱组件及现有标题返回路径。新增原创资产仅：2张平面日历/晨光渐变、3个矢量母题（窗口灯/文件副本/关闭文件夹）、1个来源标签、未读/未完成两种图标。新闻不使用真实媒体截图、论文图版、人物照片、网站Logo或社交头像；不下载视频。文字可真实署名，但版权内容需单独许可。

声音建议为自制/已授权：日历轻翻一次、窗口轻响、邮件到达一次；无朗读默认，不接网络TTS。沿用音量和静音；不强行播放用户已关闭的背景音乐。每屏不叠超过两条音轨，不用通知声制造反复催促。缺许可资产时静默替代。

减少动态模式：无粒子、无镜头摇动、无自动打字，日历两张静态交叉淡入≤0.2秒；默认模式只做3张卡透明度/位置变化，总动效对象≤12，无全屏模糊、后处理或实时3D。文本进入屏幕时一次排版，静止帧不重建；邮件按段池化，不每帧拼长字符串；隐藏浏览器/YY/邮箱不刷新；终局页面只订阅一次事件并在销毁时解绑。上述是实施预算，不是实测性能结论。

中英使用同ID双语资源，英文不截断关键信息；最小窗口可单列，触控/键盘能操作所有关键按钮，滚动位置按段落ID而非像素存。状态以文字+图标表达，不只靠颜色；旁白/世界日期/公共来源标签用高对比。玩家昵称/模型名先转义，不把名字当TMP富文本。

## 11. 默认A决策与不可覆盖边界

明确 A：三主体R1/R2/R4＋R3决策方式；旧ID原样留存；路线与关机正交；2017-06-13尾声；史实/虚构标签分离；未安装平台留档；每阶段一主动主题提示；公开信显式保存到本地游戏邮箱；打开不通关、最终按钮原子保存才通关；旧已完成不倒退；减少动态静态替代；不新增奖励；R3锁定路线后钉卡再执行；普通工作邮件替代毕业通知。

不能被“默认A”覆盖：阶段3–5既有玩法、主动加YY、实际发帖才引流、书名作者可真实署名、虚构终局人物匿名、版权许可、三关实际通过、记忆卡真实来源及固定三格等原确认。来源未证实就降为原创泛论或不使用，不能默认A变成编造事实。缺外部授权素材就用原创文字/几何资产，不把匿名当成版权豁免。
