# C3 存储闭环：候选暂缓生产合入

当前去除永久截断的候选只完成内存/序列化模型与查询接口。**不可直接合入生产**：现有 AtomicSaveStore.MaxPayloadBytes 为2,097,152字节，长期全量历史必然触及上限。保持当前失败时不覆盖旧存档的保护，但不能把该保护当作功能完成。不改全局AtomicSaveStore、不删除历史、不把历史上限改名为分页。

## 方案A：记录专用压缩字段，继续单文件原子写

- 设计：新增带版本/codec/未压缩长度/checksum的记录归档字段，压缩askedLog+teachingNotebook耐久内容，保留模型所需短上下文缓存。保存时在独立序列化快照上将旧列表替换成压缩字段，不能清空live Sim来冒险写盘；加载时先解码/校验再绑定Sim。避免同一记录同时存明文和base64。
- 旧档迁移：仅在成功读取所有旧记录后生成归档；第一次成功原子写前保持原文件和备份，旧无法恢复时间仍未知。读档识别codec版本，新版本未知时保护存档，不能当空历史初始化。已被旧200/256截断的数据不伪造。
- 故障恢复：仍由现有main/tmp/bak事务负责，压缩数据损坏或解压校验失败时使用备份；解压前检查声明长度，设置合理防异常解压上限。编码异常不写盘；回退保留原文件。
- 查询：一次解压恢复当前候选的索引，分页只复制窗口；内存随历史增长。可后续对归档内部块逐页解压，但整个主档仍须重写。
- 上限：2MB对压缩后的整个house仍生效，base64另增加约1/3。此方案延长容量但**无法满足任意长历史的可靠保存**；只有把B作为确定后续、或建立可接受且明示的磁盘容量边界时才是过渡方案。不能以本样例压缩率保证所有长档。主档内非记录状态也会增长。
- 工作面：共享Runtime保存/加载快照路径、版本保护、非Unity解压、slot复制不用额外文件，改动小于B。但只修改C3字段不够，必须以真实保存/重载/备份故障测试为门槛。

## 方案B：每存档不可变分块档案 + 主档原子manifest（建议）

- 标识：每条记录有稳定seq，每个存档lineage拥有独立archive namespace；快照/存档槽保留所引用的chunk generation。每块例如128–256条或有界UTF8字节，含版本、first/last seq、校验和、索引摘要。主档保留有界尾部、精简manifest根引用和计数。不能把无限增长chunk列表原样堆进2MB主档；manifest本身也分段/分级。
- 写事务：先将新块写tmp、flush、校验、原子rename为不可变块；再写新版不可变manifest；最后用现有AtomicSaveStore原子替换主档的manifest根/尾部。崩溃在最后一步前只留下孤块，旧主档和旧manifest仍完整；提交后必须所有引用存在且校验有效。
- 旧档迁移：旧单档读取成功后，将现有日志迁为chunk但保留旧主档；仅在所有块完成并校验后原子提交新root引用。保留旧文件备份。对缺时间/已丢历史遵循未知与不补造。
- 故障恢复：加载主档后验证引用manifest；按需读chunk时也核验。缺块/坏块触发保护，不悄悄跳过记录；可尝试仍完整的主档备份引用。write失败、磁盘满、权限问题保持旧主档有效。GC必须扫描当前主档、备份、所有slot与导出引用之后才删除无引用块；先不自动GC比错误清理安全。
- 查询：manifest保留来源、日期范围、序号范围的索引，分页只加载相关块；当前全量内存排序索引转为有界缓存。源过滤和稳定同刻顺序延续本候选API。全文搜索可渐进扫描/索引，不每次复制全库。CSV大文件预览也必须分页/流式，不能拼接无限StringBuilder。
- 复制与兼容：SaveSlot/恢复/另存/重启归档/导出/导入/用户手动移动存档目录必须支持整套引用；跨profile或新游戏不能共享可变尾部。旧游戏版本看到新格式应保护拒绝，不能无声加载为缺历史的旧档。此处是B最大集成成本。
- 上限：历史容量由磁盘可用空间而非2MB主档决定，单块/缓存/尾部有界；磁盘不足必须明确失败并保留旧已提交数据。系统不可能在有限磁盘上保证无限历史，但可以随空间增长并在资源耗尽时正确处理，不因固定主档格式在数千题必然失败。
- 实施验收：主档/块写入各故障点、坏checksum/缺块、旧档一次性迁移、跨slot回滚与fork、备份恢复、archive copy、孤块回收、10万条分页和内存预算。root协调持久化文件所有权；C3/C4不私自修改。

建议root选B作为完整路线；当前纯记录/查询契约可供C4编写候选，但所有历史存储完成前不宣称C3完成、不直接合入删除截断的生产补丁。
