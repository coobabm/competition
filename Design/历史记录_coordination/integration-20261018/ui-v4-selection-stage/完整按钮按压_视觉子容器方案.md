# 完整按钮按压：视觉子容器最小方案（只读设计）

## 推荐结构

保留现有布局与命中根 `XgBtn.rt`，新增 `XgBtn.Visual`（浅色按钮返回 rt，深色按钮返回新建 visual）及 `XgButtonPressFeedback.PressTarget`。

```
Button（原 rt：布局/固定命中框/业务 Knock/Button/XgHold/WindowFocus/事件）
  Hit Image：透明，raycastTarget=true，仅保证完整命中区域
  Visual（四边拉伸，offset=0，pivot=.5/.5，无布局组件）
    Face Image：实际背景，raycastTarget=false，Selectable.targetGraphic 指向这里
    Label / Icon / Sub / Bill：所有本按钮装饰内容，raycastTarget=false
    Outline：作用在 Face 上
```

Face 可以直接是 Visual 上的 Image，不必再造一层 Face GameObject。XgBtn.image 指向此真实可见 Image；现有 Set/着色/换圆角 sprite 调用仍有效。Button、业务组件与行的命名留在根，所有 Find/Button回调/QA点击位置仍按原根。深色 pressFx 只作用 Visual，原业务 XgJuice.Knock(rt) 继续拥有根，二者不争用同一 RectTransform；减少特效/取消清理只清自己的 pressFx。

根已被业务 Knock 时，Visual 的 .95 为父子变换自然相乘，松手归一不会清掉根上的业务运动。不要转而让两套 XgJuice 都写 rt；也不要移动 Button 到 Visual，否则命中框随缩放跳动、边缘按下可能立刻 Exit。

## 最小文件范围与接口

1. `XgUi.cs`：XgBtn 增加 Visual 属性/字段；仅 dark factory 创建 Hit+Visual，将现有 face/label/outline构造在 Visual；回传 rt 保持根，image 保持可见 face。XgHoverRim 的鼠标事件组件继续在根，rim引用 Visual 上 Outline。浅色工厂不改层级。
2. `XgButtonPressFeedback.cs`：新增 PressTarget，默认回退 Label；把 HoldPress/ReleasePress/HasActiveKnock/Settle 的实际目标统一为 `V4Press ? PressTarget ?? Label : Label`。pressFx 放对应目标；OnDisable/Cancel/Reduced/drag取消逻辑不改变业务事件。不能只替换按下、漏掉 LateUpdate 的目标。
3. `XgTrainPage.cs:131/133`：Sub/Bill 改挂 `train.Visual`，保持坐标；XgHold、XgTrainingSubmit 仍挂 train.rt。否则训练按钮只是主文+背景缩小，金额/副标题悬空。trainGlow 外部业务光晕可以保持根同级。
4. `XgLifeEventCard.cs:177`：Detail 装饰移至 b.Visual，事件按钮根保持。其他只改 label 的调用不用改。
5. `UiV4PressChecks.cs`：按真实 XgUi 工厂建有背景/边框/副标题的深色按钮，验证 Visual整体缩放及根业务运动隔离。现有只造 Label 的夹具无法证明“整块按钮”。

`XgJuice.cs` 无需改按压算法；现有 HoldPress/ReleasePress 和独立实例即可复用。若发现暂停/恢复问题，先在反馈组件处理，不扩大到全局业务 FX。

## 必须盘点的特殊消费者（不能默默算完成）

- `ZhongbaoSkin.Outlined` 外部 Frame 在 Button 根外（`:132` 一带），若深色 kit 也经此 helper 创建，外框不会随 Visual 一起缩放。现教页正由另一代理改主题：本任务不碰 XgLabelPage 或 ZhongbaoSkin。提供 Visual API，交由其主题组件选择将装饰框放入 Visual，或明确维持浅色反馈。
- `XgBoardPage.Assembly.cs:173–177` 模型卡有额外 Capability/Version/Validation/InstallState和根 Outline；还有嵌套 remove 按钮。这是复杂卡片，不应自动把全部子节点搬进 Visual：那会连带嵌套按钮命中框一起缩放。最低改动是对该复合卡明确保留旧标签反馈（V4Press=false），后续专门做卡片主体与删除按钮分层；不要宣称这一批覆盖所有复合卡。
- `XgContractsPage.cs:102/119` 给根加/取 Outline。通常在众包浅色 host 不受影响，但存在复用到 EXE 的入口，应核实实际 dark 值；若为 dark，需要改为可见 image 的 Outline引用，而非根透明 Hit。
- 任何 `button.GetComponent<Image>()` 将拿到透明 Hit，而非可见 face。工厂消费者应读 XgBtn.image/Button.targetGraphic；窗体 chrome 自己创建按钮的路径不要顺手改。
- 原 `transform.Find("Label")` 的测试/功能会因 Label 移到 Visual 下失效。优先统一 XgBtn.label，具体反射QA必须适配。根层级路径不能靠复制第二份隐藏 Label 兼容。
- 非工厂按钮（侧栏 NavRow、科技节点等直接 AddComponent<Button>）不自动获得此效果；这次最小方案仅覆盖明确采用深色工厂的普通按钮。后续可用同一视觉容器但需按组件逐个迁移，不能说每个可点击对象都已覆盖。

## 不建议的省事方式

不在每次按下时枚举并重挂全部孩子；会破坏 ScrollRect、LayoutGroup、拖动卡、嵌套按钮、固定路径与监听对象，产生每次点击布局重建。
不每帧把根 Image 颜色复制给克隆背景；容易与状态变色/Outline/变更sprite不同步，还保留了两套来源。
不单独把根 CanvasRenderer 隐掉并移动文字；原图形还承担命中和outline，后续Set可能再次使其显现。

## 有意义回归

- 实际工厂深色按钮：Face/Label/Icon/Sub/Bill世界包围框随 Visual 同步缩到.95，根 rect/scale与命中区域不动；边缘按下停留不触发误 Exit。
- 按住超过.3s，Visual保持.95；重复Down不复乘；松手约.22s后准确回1；键盘提交一次回弹且只触发一次业务。
- 根先运行 Knock，再按Visual，取消/减少特效仅停止相应运动；未开启reduce时按压取消不能把业务根恢复到初值。
- 滚动接管、指针离开、禁用、窗口隐藏、对象销毁、重建全部恢复；不重复XgHold.Up、不重复训练提交。
- 修改按钮尺寸/父级缩放后，Visual保持全铺且中心缩放；50%/100%/150%界面比例皆正常。
- 浅色普通/Outlined按钮：层级、颜色、原标签反馈不变。
- 主窗口训练按钮实际副标题/电费随动；主题代理教页保持约定，不产生两重边框。

本报告不写主项目、不启动Unity；是实施范围建议，不是已完成代码或视觉验收。
