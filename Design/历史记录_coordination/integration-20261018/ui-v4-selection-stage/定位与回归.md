# “左滑右滑 / 手写数字”选中错位：源码定位与最小候选修复

基准：`competition-latest-20261016` 当前未提交集成工作区；没有修改主项目，没有运行 Unity。目录内 `source-snapshot.json` 保存读取时四个源文件 SHA256；`selection-isolation.patch` 是候选最小补丁，`git apply --check --ignore-space-change` 已通过。此检查不等于 Unity 编译或视觉验收。

## 结论与证据边界

当前源码已经将大厅与普通卡片都改为同一个 `Desk` 属性：教读 `S.desk`、众包读 `S.workDesk`（XgLabelPage.cs:129–132）。`XgMiniGames.ForDesk("mnist")` 返回 null，标题滑动仅对应 headline。**因此不能仅凭旧截图宣称当前代码仍能稳定复现“手写数字选中、右侧标题滑动”完全相同的场景。** 未取得原截图运行版本、状态和交互序列，需实际运行回归验证。

但当前仍有三个可由源码确认的同类错位/串状态缺陷，足以解释为何旧页内容、独立选择状态和右侧玩法可能不同步：

1. **众包仍可挂教学小游戏，且结算绕过工作系统。** `XgLabelPage.DeskGame.cs:46` 不排除 WorkContext；`:61` 读取全局 `S.teachingPack`，否则从当前工作桌映射教学小游戏。`XgDeskGamePage.Open` 创建教学 ticket，Settle 调用 `SubmitMiniGame`；`XgSim.MiniGames.cs:99` 进入 `SettleMiniAction`，不是 `TryAnswerWork`。即使左右标签暂时一致，也会把公司任务和自己 AI 的教学玩法/样本路径混在一起。
2. **手写视图检查了另一系统的选择。** `XgLabelPage.Handwriting.cs:57` 用 `view != null` 排除 EXE，却读 `Sim.S.desk` 判断是否手写；在众包应读 workDesk，但它可能随 EXE 教学选择出现。`:204` 报酬又按局部 Desk，`:400` 提交固定走 `SubmitHandwriting`。这会同时出现“工作任务、手写内容、教学样本”三种来源。既定新规则是众包公司判断与 EXE 教学分离，不能仅把 S.desk 换成 workDesk 后继续允许工作给 AI 训练。
3. **视图切换被焦点延迟。** `XgLabelPage.cs:383` 原只在教上下文 Stop 旧小游戏，工作切桌不停止；`XgLabelPage.DeskGame.cs:68` 又要求 Focused 才 Open 新游戏。可见窗口被另一窗口遮挡/失焦时，左侧 Desk 立即变更，原游戏却能留着。正常点击或重新聚焦可能下一帧消除，所以应区分暂态和持续错误。视图绑定不应依赖键盘/交互焦点；游戏实际 Tick 和提交仍保留 Focused 防线。

另有确定的**双高亮**：选数据包后 `SelectTeachingPack` 同时设置 `teachingPack` 和 `desk`（XgSim.DataPacks.cs:59），基础桌行仅判断 row.id==Desk，包行又判断 teachingPack==row.id。于是基础桌和扩展题桌会同时亮，让用户认为选的是基础桌。这与截图的“看起来选中错误”属于同类问题。

## 候选补丁内容

- `XgLabelPage.DeskGame.cs`：WorkContext 不允许教学小游戏覆盖公司卡片；切换新游戏视图不依赖 Focused，输入和结算原焦点门槛保留。
- `XgLabelPage.Handwriting.cs`：WorkContext 禁止旧手写覆盖；统一读取 Desk。保留旧 `view != null` 约束，当前 EXE 手写走其教学包实现，不重新引入第二种手写入口。
- `XgLabelPage.cs`：所有上下文切桌先 Stop 旧小游戏；工作同桌早退不再受教页 teachingPack 影响；工作切桌不清教页选择。
- `XgLabelPage.Hall.cs`：教页选中了扩展包时基础桌不再重复高亮；众包高亮保持按自身 workDesk。

没有恢复众包→教共享进度，没有删除众包公司任务，也没有重排 19 种教学玩法。没有修改数据格式、新增字段或改存档。

## 根任务需要串行执行的回归

1. 新档/已有档，教页选择标题滑动→手写数字→常识→标题滑动，逐帧检查唯一高亮、实际游戏 ID、题干/标题、样本归属一致。标题滑动→手写时不允许残留旧 surface 或旧游戏 ticket。
2. 同时打开 EXE 和众包。EXE 固定 headline/teachingPack，众包选择 mnist，再反向组合。众包必须是其 WorkCard、无 DeskGame/旧 Handwriting 覆盖；教页选择与 teachingPack 不变。
3. 在众包正确/错误各提交一次，只核对工作计数和公司收入变化；教学 handCorrect/handWrong、teachingNotebook、小游戏记录、教学样本不得增加。教页提交则保留既有教学奖励。
4. 选扩展题包，只有该包高亮；切回基础桌，teachingPack 清空且只亮基础桌；众包同桌点击不改任何教页选择。
5. 窗口失焦、YY 遮挡、切页、最小化/还原、存档重绑后，检查旧游戏 surface/ticket 已撤销。无焦点可以更新正确画面，但不得通过快捷键或旧回调结算。
6. 开局手写教学包、切短信/标题滑动实际操作均能开始、下一题正常、计费正常；中英切换不影响 ID 映射。工作界面手写题应仍可用普通 WorkCard 正误按钮回答。
7. 已锁桌点击不改变选择；重排大厅/升级/购买新包后，按钮闭包仍按稳定 ID 对应行。本次检查看到循环使用局部 string id，不是常见捕获 i 导致末行回调问题。

附带但未纳入补丁：`LoosePacks()` 当前只在 WorkContext 列出 AI 已购非题桌数据，仍会把 AI 私有数据状态展示到公司大厅；应按两系统分离清理，但这不是此次选中错位最小修复。另 `Refresh()` 在小游戏分支提前 return 之前才执行存档重绑大厅检查；`RefreshHall` 只按阶段/数量触发部分重建，换同阶段存档时需纳入第 5 项验证。
