## 分卷发布方案

本机已有 `C:/Program Files/7-Zip/7z.exe`。整个游戏目录打包成一个 7z 归档并按 `-v1500m` 分卷（每卷 1,572,864,000 字节，小于 GitHub 单资源 2 GiB）；推荐 `-mx=1`，GGUF 本身压缩收益不高。输入必须包含整个构建目录，不要只打 exe。参数概念：`7z a -t7z -mx=1 -v1500m <新发布目录>/MyComputerAlive-2026.10.18.1-Windows.7z <实际构建目录>`。输出目录必须在输入目录之外。

打包后 `7z t <archive>.7z.001` 完整测试，计算每卷 SHA256 并生成 SHA256SUMS.txt；抽查每卷均 <2 GiB。GitHub Release 上传全部 .001/.002/...、校验文件和玩家说明。不要把 GGUF / 构建包直接 commit 到 Git。

玩家说明：把全部分卷放同一文件夹，用 7-Zip 打开 .001 解压；保留 exe、同名 _Data 目录、UnityPlayer.dll、MonoBleedingEdge 等全部内容；运行 MyComputerAlive.exe。已有存档沿用当前 company/product。解压前建议至少留出完整解压目录+下载压缩卷的双倍空间。发布说明应写内置 Qwen3-4B、Windows CPU 推理，并说明首轮回复可能较慢，不写成 Qwen3.5 或联网必需。
