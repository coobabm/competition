# Final Player external tools — staging only

## Window tool

`Player-WindowQa.ps1` accepts an already running `-TargetProcessId`. Default `-Action Inspect` lists only that process's visible top-level windows, handles, client sizes and foreground state. It never launches the game and has no automatic click sequence.

Examples (replace values with the real PID/handle returned by Inspect):

```powershell
& ./Player-WindowQa.ps1 -TargetProcessId 12345
& ./Player-WindowQa.ps1 -TargetProcessId 12345 -WindowHandle 67890 -Action Capture -OutputPath 'C:/absolute/new-output/title.png'
& ./Player-WindowQa.ps1 -TargetProcessId 12345 -WindowHandle 67890 -Action Focus
& ./Player-WindowQa.ps1 -TargetProcessId 12345 -WindowHandle 67890 -Action Click -ClientX 600 -ClientY 400
```

Each invocation rechecks HWND ownership and process start time; ambiguous multiple windows require an explicit handle. Click requires the exact target already foreground, valid client coordinates and an unobstructed target point, then rechecks immediately before sending one click. It does not automatically focus from Click or choose desktop coordinates. Windows can still switch foreground asynchronously, so run one deliberate click at a time and inspect again after navigation; never feed blind bulk coordinates.

Capture uses the specified window's client area through PrintWindow, never a whole-screen fallback. Refuses blank image, minimized/unresponsive window, relative/non-PNG/existing output. Unity GPU surfaces can reject PrintWindow; report this honestly and use a deliberate ffmpeg `gdigrab hwnd=<decimal handle>` window capture if supported by the installed demuxer. Native declarations compiled successfully; PowerShell syntax passed. No Focus/Click/Capture action has been executed.
