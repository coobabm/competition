## 具体风险与纠正

1. **§8b 的门禁触发未成立。** WindowManager:209 确实先调用 AllowsWindow，但 StudyDesktopGates:35–46/74–92 只给商店、电力、众包、数据映射 feature；Tieba/Reminder 没有对应门槛，Feature 为 null 时 Allows 返回 true。因此不可宣称当前 Tieba 已被门禁拦截并复现报错。未激活物体启动协程是合理防御边界，可用明确的 inactive 场景由主控验证，无须为复现人为改变生产门禁。
2. **未读没有发现候选所暗示的回归。** 生产 Go:168–169 和 DrawChat:534 都调用 IsWindowVisible 后才 MarkSeen；DesktopNotifications:49 在 inactive 时直接返回 false。EnsureShown:461–480 只启动恢复检查，inactive/isOn=false 时退出，不会强制激活受阻窗口。保留此检查，报告把“受阻期间不清未读”列为待验证断言，而非已修复 bug。
3. **afterSeconds 是三条，不是四条。** 当前 forum.json 正值为40、90、150秒；第4处文本出现位于说明 note。Forum.cs:138–145 的显示判定与候选 `helpPosted && secondsSinceHelp >= afterSeconds` 一致。候选动态收集代码不依赖数量，因此主要是报告证据纠正。
4. GateKey 缓存仅在 library 身份/线程数量变化时重建。当前 Library 在 Awake 创建，老周线程在注册时添加，未发现运行时原位修改已有 requires/楼层集合的生产路径；公开可变集合仍使“任何更改都可感知”的泛化不成立。侧栏数量相同的替换也同理。按现有工程做有限保证，不引入全局缓存框架。
5. §8a 修复的是静态事件保留旧实例的生命周期问题；lambda 只是写字符串，不应把必然抛 MissingReferenceException 当成已复现事实。Repeated Install 若换到另一个 hub，候选仍订阅旧 hub；目前调用路径不要求这种动态重绑定，不应夸大支持范围。
6. 非聊天页保留滚动位置是新交互需求，不包含在当前修复。默认保留现状，无需阻塞交接。如果用户主动要求改变，才讨论滚动定位策略。
