## 实际实现

- YY已有老周联系人、同一当前存档和已安装YY才提供可选操作。未完成原有问答时优先保留问答选项。阶段本身、进入结局、读过新闻、旧NPC台词都不会产生私人证据。
- 准备流程真实读过SI信后，玩家可在老周YY里选择“聊聊上线/公开/再等一等”。已有路线选择时只展示相应计划。点击先显示完整原文预览；取消/关闭/换档/切换语言不发送。长文须滚到末端再启用发送。
- 点击“发送以上原文”才在同一个YY存档对象中写入玩家消息、老周固定回复和持久收据。收据包含随机稳定ID、`yy:ending:<id>`来源引用、收到的模拟秒数、确切发送原文、实际回信、路线/决策作用域。`kind+scope`去重；同一按钮重复回调、读档后重复选择不重发。保存沿用现有聊天保存事务：保存失败时不会只落下收据而缺消息；重试同一内存状态仍幂等，未自动保存前崩溃与普通聊天一样可能丢失整个尚未保存的交流。
- 真正发布成功后才开放路线披露，R1还要求真实上线夜结束或拔电源收据。披露本身可选，不参与发布/通关门槛。R1/R2/R4披露后分别回复原稿3句。R3仅先告知“我请它决定”，回复原稿3句；之后提供独立的原话转发预览，只有决策ID匹配实际已提交发布回执时可转发，收到后补原稿相应1句。拒绝转发不会猜测其答案。
- 关机卡采用另一独立预览/发送。只报告已钉卡结果；路线披露不会自动揭露关机卡。发送后才出现对应原稿附句。全部18句中文与原20261018§6逐字核对一致，英文同步。
- LP1/LP2/LP4只接受已实际发送的`planned`收据，且只使用最近一次真实计划披露。已经做完后的路线披露不会伪装成之前的计划。邮件桥调用既有`EligibleAppendix`，阅读器在公开签名之后显示明确标识的私人附记。无证据仍是原公开信。公开文章资源、原有9段/信（双语共54段）、通关事务和三封公共档案均未修改。
- 私人阅读位置映射到已有`signature`锚点，保持旧档和既有位置协议兼容；读到末端判定包含附记，不能读到公开签名就绕过附记。回看仅投影保存的证据，不发消息、不改收据、不写新路线。
- 收据保存在`YYState.endingPrivate`，旧档空/null均安全，不迁移/推断旧聊天或旧flag。持久私人交流快照独立于滚动聊天历史，因此普通YY历史裁剪不丢幂等与来源证据。

5. 不通过自由文本关键词猜测披露。只有本预览发送入口生成精确收据；任意手打、反问、否定、引用、旧聊天均不触发18句/LP附段。这一保守边界避免误判，普通聊天仍照原路径工作。
