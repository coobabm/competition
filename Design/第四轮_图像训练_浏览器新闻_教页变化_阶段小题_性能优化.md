## 一、视觉题要有真的图

### 1.1 现在的问题

手写数字、验证码、表情包、看图说词这些「视觉」题，题卡上大多只有文字描述（「[一张猫的照片] 这是什么？」），训练也只看到数字。玩家感觉不到它在「看」。

### 1.2 改法：每道视觉题都显示一张图

| 题库 | 图从哪来 | 题卡上 |
|---|---|---|
| 手写数字 | 程序画（main 已有 `XgHandwriting`）：28×28 像素，笔画粗细、倾斜随机 | 放大成 224×224 的像素格，带网格线 |
| 验证码 | 程序画：4 位字母数字 + 干扰线 + 扭曲 | 原尺寸显示 |
| 12306 图片验证码（CIFAR 桌） | `Resources/Media` 下 8 类小图各 10 张（飞机、汽车、猫、狗、红酒、毛巾……） | 3×3 九宫格，问「这张是不是 ×××」 |
| 表情包 | 程序画的简笔表情（眼、嘴、眉三个零件组合）+ 配字 | 表情 + 配字 |
| 看图说词（ImageNet） | `Resources/Media` 下每类 5 张照片（狗、猫、汽车、手机、苹果……；「苹果」里有手机，故意的） | 照片 + 四个候选词 |

### 1.3 「练」页上看得见它在学图

- **答卷**：视觉题的答卷每行左边放一张缩略图（48×48），右边是「它答」。
- **「看它学」窗口**（买「权重可视化」后）：
  - 选中答卷里一张图，图上叠一层半透明热力图：它判断时最看重哪些像素。
  - 阶段 2（多层感知机）：热力图是散的，到处都亮，挪一格就全变 → 对应小题 q2c。
  - 阶段 3（卷积）：热力图集中在笔画上，挪一格热力图跟着挪。
  - 捷径偏见（草地上的狗）：热力图亮在草地上，不在狗身上。玩家一眼看出它「看错了地方」。
- **每轮训练的小动画**：练一轮时，答卷里的缩略图逐张闪一下，答对变绿框、答错变红框。
- 热力图用简单的遮挡法算：把图分成 7×7 块，每次遮一块看它把握变多少；变得多的块就亮。代价可控（一张图 49 次推理，只在打开窗口时算一次并缓存）。

## 二、浏览器：内置 2016 新闻网页

- 数据：`browser_news.json`（45 条，6 月到 12 月，每月 6–7 条）。
- **浏览器首页**就是「摆渡新闻」：顶部一条大标题，下面列表。游戏日历到了那天，新闻才出现；最新的在上面。
- 内容配比：娱乐、体育、科技为主；每月一两条「水文」（「震惊！」「月薪三千和三万」），带灰色「推广」小字，读完是一句吐槽式结论，图个乐；政治和讣告只有一行标题、点不开（`brief`）。
- 点开文章：标题、日期、两三句正文、底下「相关阅读」三条。正文中如果提到训练相关的词（神经网络、翻译、AlphaGo），右边出一个小按钮「转给它看」：把这段文字作为一条资料教给它（《年代玩法策划》柱子四：它的见识来自你给它看的东西）。
- 随阶段变化：阶段越高，科技新闻在首页越靠前；阶段 6 起首页右侧多一个「热搜」栏。
- 浏览器地址栏仍只认游戏内的地址（`news.bodu.com`、`888.vip` 等），不访问真实网络。

## 三、「教」页随购买和阶段变化

### 3.1 问题

现在不管到了哪个阶段、买了什么，「教」页都是同一张卡、同样的「对 / 错」两个按钮。

### 3.2 每个阶段换一种出题方式

| 阶段 | 「教」的题卡 | 玩家的操作 |
|---|---|---|
| 1 是 / 否 | 一句话 | 对 / 错 |
| 2 多选一 | 一句话或一张图 + 四个选项 | 点一个选项（快捷键 1–4） |
| 3 一个词 | 一张图 | 从 6 个词里点一个，或自己打一个词 |
| 4 短句 | 它写的一句话，有一处错 | 点出错的那个字词，或选「没错」 |
| 5 长记忆 · 翻译 | 一句中文 + 它的英文翻译 | 打分：准 / 有点歪 / 错了；「有点歪」可以点出哪个词歪了 |
| 6 全会 | 一个问题 + 它的两个回答 | 挑好的那个（就是「挑好答案」） |

- 旧阶段的题型不消失：题桌按题库保留自己的题型（垃圾短信永远是对 / 错；表情包永远是看图选词）。新阶段开的新题桌用新题型。
- 每次进入新阶段，「教」页第一次打开时，新题型的题卡从下方滑入，旁边一行字说明新操作（只出现一次）。

### 3.3 买了东西，「教」的题卡上多一个小工具

沿用《训练技巧策划》第四节，再明确一次：

| 买了 | 题卡上多了 |
|---|---|
| {名字}代答 | 题目下方一行大字：「len：对 · 72%」 |
| 偏置 | 题卡底部一根可拖的「门槛」线 |
| S 形函数 | 它的回答带把握；任务大厅出「先教拿不准的」排序 |
| 数据增强 | 视觉题卡右上角「变」按钮 |
| 数据清洗 | 任务大厅顶部「疑似错题」托盘 |
| 新题库（数据包） | 任务大厅多一张带「新」的题桌 |
| 难例复核 | 题卡角上「复核」标签 |

## 四、「练」页的阶段小题

- 数据：`stage_quiz.json`（21 道，每阶段 3–4 道）。
- **出现时机**：进入新阶段时出一道（`stage_enter`）；撞上对应现象时出一道（`plateau` 分数卡住、`gap` 背答案、`nan` 练崩、`deep_flat` 加层不涨、`shift` 挪一格不认识、`long_fail` 长句忘、`deep_worse` 越深越差、`translate_fail` 翻译不了、`serial` 卡闲着、`noise` 错题多、`continues` 接着出题、`flatter` 讨好）。
- **样子**：曲线上方一张小卡，不盖住按钮：

```
┌────────────────────────────────────────┐
│ ？ 分数为什么卡在 50% 不动？               │
│  [一条线分不开]  [题太少]  [电费不够]       │
└────────────────────────────────────────┘
```

- 选对：卡片翻面，显示解答（≤ 2 句）+「+¥20」，科技树上对应节点闪一圈金光，卡片底部按钮「去看看 →」直接跳到那个节点。
- 选错：同样翻面显示解答，不扣钱，按钮一样。
- 做过的题收进科技树「图鉴」，可以重看。
- 目的：玩家做完这一阶段的小题，就知道这一阶段科技树上那几个节点是在解决什么问题。

## 五、科技树词条：再精简

所有节点卡统一三行，不再有任何长段落：

```
多层感知机 MLP · 1986
多叠几层，能组合线索。
▶ 解锁「多选一」                       ¥120
```

| 行 | 规则 |
|---|---|
| 1 名字 | 中文名 + 缩写 + 年份 |
| 2 一句话 | ≤ 12 字，说它是什么 |
| 3 效果 | 「▶」开头，≤ 14 字，说买了以后能做什么；有数字写数字 |

- 科普全文只在点「详情 ›」后显示，且不超过 3 句。
- 文案按《练页教学指引与科技文案简化》4.3 的表 + 《训练技巧策划》总表的「▶ 现在能……」列，二者冲突时用后者。
- 删除 `XgTechTreeCopy` 里所有「不保证」「需训练后评估」「与其他倍数相乘」等说明。

## 六、性能优化（游戏有点卡）

### 6.1 先量，再改

1. 打开 Unity Profiler（Deep Profile 关），在三个场景各录 30 秒：开局「教」页连点答题；「练」页自动训练；YY 群聊和贴吧来回切。
2. 看三样：每帧 CPU 时间最高的脚本、`GC.Alloc` 每帧分配量、`Canvas.BuildBatch` / `Canvas.SendWillRenderCanvases` 的耗时。
3. 把前十个热点记进 `Design/整合记录.md`，改完再录一次对比。

### 6.2 代码里已经看到的问题（按可能的影响排序）

| 问题 | 例子 | 改法 |
|---|---|---|
| 每秒 / 每帧全场景查找物体 | `StudyDesktopGates.LateUpdate` 每秒 `FindObjectsByType<ChapterOneDesktopBridge>` 和 `<WindowManager>`；`StudyDesktopGates.Allows`、`TiebaHub.Lab()`、`CasinoDesktop.Update` 里 `FindAnyObjectByType`；多处 `GameObject.Find("Desktop List/...")` | 启动时查一次缓存引用；只在阶段变化（`StageAdvanced` 事件）时刷新图标显隐 |
| 页面每帧整页 Refresh | 各 `XgPage.Refresh()` 每帧重设所有文本 | 只在数据变化时刷新（脏标记）；不可见的页面不刷新；同一个值没变就不赋 `text` |
| 每帧拼字符串 | `numbers.text = "<b>" + ... + ...`、`TiebaView` 的 signature | 用缓存比较，值变了才拼；避免每帧 `string.Format` / `+` |
| TextMeshPro 自动字号 | `enableAutoSizing = true` 用在很多一直变化的文字上 | 去掉自动字号，固定字号；必须时只在文本变化时计算一次 |
| 一个大 Canvas | 整个桌面、.exe、YY 共用一个 Canvas，任何一个数字变化都让整块重建 | 拆 Canvas：桌面背景、每个应用窗口、悬停提示、托盘各一个子 Canvas；会动的东西（曲线、进度条、计时）放单独子 Canvas |
| 自定义图形每帧重画 | 曲线、壁纸大脑、环形进度（`MaskableGraphic` + `SetVerticesDirty`） | 只在数据变化时 `SetVerticesDirty`；壁纸大脑降到 15 帧更新一次；看不见时停止 |
| 每帧 new List / LINQ | `new List<...>(windows)`、`FindAll`、`Exists` 在 Update 里 | 复用列表；去掉 Update 里的 LINQ |
| 存档在主线程 | 自动存档序列化 JSON | 序列化放后台线程，或拉长间隔（5 分钟）、只在空闲时存 |
| 本地模型 | 生成时主线程等待；同时多个请求 | 确认全部异步；同时最多 1 个请求在跑，其余排队；YY 群和贴吧回复优先级低于它自己 |
| 隐藏窗口仍在跑 | 最小化的 .exe、贴吧、游戏中心仍在 Update | 窗口不可见时停掉它的 Update（`enabled = false`）和动画 |
| 粒子与飘字 | 连击飘字、金粒子堆积 | 对象池；同屏飘字上限 8 个 |

### 6.3 设置里加两个开关

- 「画面：高 / 低」：低时关闭壁纸大脑动画、粒子、热力图实时刷新，曲线 10 帧更新一次。
- 「帧率上限：30 / 60」：默认 60；`Application.targetFrameRate`，同时 `QualitySettings.vSyncCount = 0`。

### 6.4 目标

在 1080p、集显笔记本上「练」页自动训练时稳定 60 帧；每帧 GC 分配低于 1 KB。
