# 独立测量方法（尚未运行）

由主聊天在统一验证时执行。本任务没有启动 Unity、游戏或访问玩家存档。请使用空白隔离场景，不创建游戏控制器。先记录 Unity 版本、脚本后端、编辑器/Player、CPU、构建选项和生产文件 SHA256；基线与补丁必须保持相同环境。本方法不提供虚构 FPS 或预算阈值。

## 1. 可复现的同步分配探针

将本目录 `MotionButtonPerfProbe.cs` 由整合负责人临时放入验证副本的 Editor 目录，经统一编译后，在空场景的编辑模式执行 `Tools > Design Pass > Measure Motion Button Allocation (isolated edit mode)`。脚本本身不进入 Play Mode；完成或抛出异常都会在 finally 销毁自己创建的根对象。它不创建 EventSystem、业务监听器或存档接口；导航关闭，因此不会主动改变选中对象。依赖生产公开的 `XgUi.Button`、`XgButtonPressFeedback.Label`、`XgJuice.Knock`，只读绑定私有 `Update` / `LateUpdate` 方法；私有方法若重命名应先调整探针，禁止把失败当作零开销。

保留完整日志。基线连续运行 5 次；整合补丁并编译后重复 5 次。每次记录脚本输出的 8 行结果、异常及源码指纹。比较中位数，并保留最小/最大值，不只展示最快一次。

| 独立样本 | 测量边界与解释 |
| --- | --- |
| 空委托 | 定时器/委托调用基线；小于计时噪声的差异不解释为提速。 |
| 64 个预构建按钮的首次输入 | 每个按钮第一次添加私有 XgJuice；不含 XgUi 构建文字、按钮或 TMP 初始化。预热按钮不计入这 64 个。 |
| 动画内重触发 2048 次 | 同一组件、同一 Punch 条目持续存在；无真实帧推进。 |
| 2048 次活动 XgJuice.Update | 每次在计时外先重新按下，再调用真实生产 Update 一次。时间步长最多 .05 秒，小于 .18 秒寿命，确保每次测到活动分支。基线的临时 List 分配应出现在该列。 |
| 2048 次活动取消 | 在计时外确保可交互并开始效果，测量 interactable=false 触发的真实取消/清理；不把开始效果的分配计入取消。 |
| 2048 次取消后重新按压 | 在计时外取消/恢复交互，测量重新按压。字典容量可复用，但新的 Punch 仍会分配；不能据活动重触发一列宣称所有点击零分配。 |
| 2048 次空闲 LateUpdate | 已取消效果。按钮仍启用，测量空返回开销；不能据此估算 Unity 消息调度成本。 |
| 2048 次宿主不可见时按压 | 使用无分配的 Visible 委托，观察隐藏时没有重新启用效果；包含基类 PointerDown。 |

每个计时区间使用 `GC.GetAllocatedBytesForCurrentThread` 和预绑定委托；反射查找、闭包创建、组件查询、日志拼接、样本准备均不在计时区间。输出只能称“当前线程托管分配”和“同步方法微秒/样本”，不包含所有本机分配、渲染、Canvas/TMP 后续重建、其他线程或真实帧耗。探针直接调用生命周期方法，仅用于定位分配；它不能证明自然回弹、帧顺序或完整输入链正确。编辑器计时噪声也可能超过小改动收益。

探针预热了完成分支和字典容量。它使用一次负寿命 Knock 仅在计时外立即完成预热，不把该调用作为正常按钮行为验证。按钮自己的 .18 秒/.12 秒行为仍需以下真实帧验证。

## 2. 真实帧、可见性和本机开销

由主聊天在同一空白隔离验证场景建立宿主 XgJuice（不要调用 Init），通过 XgUi 创建 1、100、1000 个按钮，预分配事件数据和操作序列。1000 是压力样本，不宣称生产场景含有这个数量。分别采集：未使用静置、全部首次触发、全部已使用后静置、每 0.3 秒再触发、动画内逐帧重触发、同时自然结束、活动中禁用、活动中隐藏宿主、隐藏后持续输入。按实际 `fx.enabled` 及最终变换判定结束，设置最多 120 帧/5 秒的失败超时；不要只固定等 .18 秒，因为生产逻辑将每帧 dt 封顶 .05 秒。

Profiler 使用 CPU Timeline/Hierarchy 和 GC.Alloc 调用栈；正式对比关闭 Deep Profile，定位阶段可另外开启。预热至少 300 帧，每段记录至少 600 帧，基线/补丁各重复 5 次。报告主线程帧耗中位数/p95、脚本方法耗时和 GC.Alloc，而非把 Edit Mode 探针换算成 FPS。记录无输入控制组；不要把每帧 GetComponents、LINQ、日志或反射造成的分配算给反馈。先分配采样数组，段结束后统一输出。

- 组件：每个未用 Label 为 0 个 XgJuice，首次后为 1，100 次自然结束/取消重开后仍为同一实例；Button 子类替代原 Button，不能同时出现原 Button + 子类。固定 Label 所有权为前提；Label 动态替换属于其他生命周期任务。
- 可见性：宿主 Visible=false/disabled 时首次输入不能创建私有反馈；进行中切换不可见，应在后续 LateUpdate 清理。宿主 delegate 用计数器确认只在按压/活动期检测；其自身若扫描对象或分配，应单独记录。CanvasGroup.alpha=0、屏幕外和无宿主不自动等价于 Visible=false，避免用错误的“不可见”条件测性能。
- 清理：使用非默认位置 (7,3)、缩放 (1.2,.9,1)，真实变形后自然结束、禁用交互、隐藏 GameObject，确认复位和停用；宿主业务 Knock 必须继续存在。根对象销毁后，引用数组清空，再以 Memory Profiler 验证对象数回到相同基线；快照不放在计时段内。不把 Unity Destroy 的帧末销毁延迟判为泄漏。
- 缓存列表边界：单个私有栈反复活动/完成；多个共享业务 Knock 同帧完成；一部分提前结束而另一部分仍活动；目标在结束前被销毁。确认清理后不存在遗留条目/变换，也没有误删仍活动的目标。需要时在计时区间外反射检查 completedPunches.Count==0；缓存容量保留合理，不保留已完成 RectTransform 引用。
- 首次本机开销：用 Profiler/Memory Profiler 补充 AddComponent 和 TMP/Canvas 重建成本，不能只用托管 GC 字节推断全部内存。Submit 基类含既有协程，需另做完整事件的场景测量；当前探针以 PointerDown 隔离通用反馈，不声称覆盖 Submit 全部开销。

共享 XgJuice 的缓存容量最多随某次同时完成目标数量增长，并保留至组件销毁。泛用标签栈只有一个目标，容量增长有限；多目标业务宿主要额外确认保留容量可接受。若实际测量显示另一处热点，应记录结果后另行处理，不预先重写整个动效系统。
