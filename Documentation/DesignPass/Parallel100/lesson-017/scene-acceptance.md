# lesson-017：首分钟真实场景验收脚本

范围仅为已授权第 13 行：新开局 → 看猜测 → 评价 → 明确反馈／纠正后壁纸亮一下 → 下一卡。此文件是供主聊天执行的人工场景脚本，不是已经执行的测试报告。所有用例初始状态为 NOT_RUN。

## 0. 运行前置条件

1. 主聊天统一完成 Unity 编译并记录版本、源码 SHA256、场景、语言、分辨率、窗口尺寸、帧率和输入方式。先运行本目录 `verify-dependencies.ps1`；STALE 时重新核对变动代码，不能直接套用补丁。
2. 使用完整生产桌面场景及正常的新游戏入口。录制从启动到首张教学卡出现的全过程。不要把 setup 中的首次“是／否”和灯泡点亮当成这次教学评价或壁纸反馈。
3. 使用专门的临时用户环境或主聊天已验证的完全隔离存档目录；不得删除、复制、读取真实玩家存档。隔离必须在任何 Awake／初始化之前生效。`ChapterOneRuntime.VerificationSaveDirectory` 仅在 UNITY_EDITOR 中参与初始化；在进场之后才设置它无效。其他存储入口也须由主聊天核对隔离。
4. 干扰验收必须保持 `runtime.TestMode == false`，保留真实剧情、YY、托盘、音效和提示调度，不用 QA 快进、不禁用组件。`AiJoinsYy.CanPlay` 会拒绝 TestMode，`OpeningQuiet.Rule` 也在 TestMode 下改变结果；因此测试模式或仅创建 XgSim 的检查不能代替本脚本。
5. 前置条件无法满足时记 BLOCKED，写明缺失接口／隔离证据；不得临时切成测试模式后记录“无干扰通过”。本任务没有启动这些运行。
6. 默认动画开启、音效开启；默认窗口布局先验收。为了看见壁纸而移动窗口的第二轮只算诊断，不能替代默认布局的可见性结论。

## 1. 统一时钟、判断依据和记录

- `t_boot`：新游戏开始；`t_setup_end`：命名及 setup 首次回答结束；`t0`：第一张正常教学卡题干、AI 猜测、两个可用评价按钮首次同时可见且可交互。首课观察窗为 `[t0,t0+60s]`，同时保留前两者到 t0 的耗时，避免把“启动第一分钟”与“首课第一分钟”混写。
- 全程连续录像并带单调时钟；截图只是关键帧补充，不能证明亮起、回落或没有短暂打断。记录第一卡 ID、题干、显示猜测 G、真值 T、所按按钮 E、结算后卡 ID。真值由题目内容和只读 QA 观测核对，不改真值、不强制 AI 猜错。
- E 为“猜对了”时玩家提交标注为 G；E 为“猜错了”时为 !G。评价正确的外部判据是 E 与 `(G == T)` 一致。`TryEvaluateTeachingGuess` 返回 true 仅表示消费输入，不能充当答对判据。
- `t_click`、反馈首帧、壁纸亮起首帧、亮起回落帧、下一卡首帧分别记录。源码同步事件不等于画面同步可见。
- “马上亮一下”的工作验收阈值：纠正后首个可渲染帧开始响应，最迟 0.25 秒内可见，2 秒内回到稳定显示；这是本脚本提出的可测阈值，不是原文给定数值。低帧率或录制漏帧时记 INCONCLUSIVE 并复测，不擅自判通过。
- 只读事件探针若由主聊天接入，应订阅当前 `XgSim.LessonTaught`，记录原卡 ID、result.correct、result.corrected、到达时间和此时下一卡 ID；换实例解除旧订阅。探针不得调用 Answer 或刷新页面来驱动流程。缺失探针时可完成视觉验收，但事件次数／计数一致性仍记待验证。
- 在 `observations.csv` 每条记录中注明 evidence_type：STATIC／RUNTIME／VISUAL；状态使用 NOT_RUN、PASS、FAIL、BLOCKED、INCONCLUSIVE。PASS 必须关联实际录像／日志路径。

## 2. A：自然新开局，快速完成首卡，再观察到 60 秒

| 时机 | 操作 | 必须观察／记录 |
| --- | --- | --- |
| 新游戏至 t0 | 按正常入口完成必要的 setup，期间不主动打开训练、聊天、科技页面 | 首张教学卡无需收样本或训练便已有猜测；记录所有自动出现的窗口和提示，不能跳过它们再计时 |
| t0 至约 8 秒 | 只读题和猜测，不点击 | 明确是 AI 猜“是／否”；按钮为“猜对了／猜错了”；第一卡引导只要求评价；题目与猜测不被覆盖 |
| 约 8 秒 | 根据真实题意点击正确的评价按钮一次 | 保留鼠标位置及按钮文本；不要直接调用核心 API |
| 点击后 0～3 秒 | 不继续点击，观察反馈及壁纸 | 猜对被认可时“它答对了”；真实纠正时“你纠正了它”，并显示正确答案；壁纸需有可辨认的瞬时提亮，不能用金币、全屏闪、setup 灯泡或 TeachingCompanion 32 格闪光代替 |
| 同期 | 观察下一卡是否自然出现 | 下一卡 ID 与旧卡不同，新题干、猜测和按钮一致；上一题结算可短暂保留，但必须不会被理解为新卡的答案。反馈仍须可读，不能因立即刷新而消失或被截断 |
| 反馈自然结束后 | 继续评价下一卡一次 | 新按钮作用于新猜测；旧反馈不会覆盖新结算。记录两张卡各自事件和学习次数 |
| 剩余时间至 t0+60 秒 | 留在标注页，不打开其他功能 | 记录所有自动抢焦点、遮挡、提示音、托盘气泡、剧情和额外行动引导；不能因为首卡已完成就提前结束观察 |

自然第一张若猜对，只能证明“确认”路径；纠正路径必须另做 B，不可把“猜错了”按钮硬点为成功纠正。

## 3. B：真实 UI 的三条边界路径

每条用独立隔离新局；按真实按钮／快捷键进入生产 `OnAnswer`，不直接调用模拟器回答函数。

1. **猜否、真值是，准确纠正**：首选自然生成的卡；若当前新局固定种子无法出现，由主聊天在隔离 QA 场景只替换卡输入：dataset=spam、seed=9137、truth=true、question=“恭喜您中奖，请点击领取”、唯一卡 ID。使用生产 Board 计算且现场确认 G=false；若不满足则记录夹具失效，不修改预测器。此分支只能称“确定性 UI 场景”，不能冒充自然新开局。点击“猜错了”，期望真实纠正成功、样本增长、一次 LessonTaught，事件携带旧卡，壁纸短亮且自然到下一卡。
2. **猜否、真值是，错误认可**：同样题目及真实预测，点击“猜对了”。期望“它其实猜错了／题目答案是是”，误判计数增加；不学习、不增加纠错计数、不发成功事件、不出现与本次作答绑定的壁纸成功闪。仍然到下一卡。将自然背景动画与成功闪分开记录；不要求全屏静止。
3. **猜对、准确认可**：自然卡 G=T，点击“猜对了”。期望“它答对了”，成功学习、一次事件、corrected=false，不显示“你纠正了它”。原文只要求纠正后亮；认可是否亮不单独据此判失败，但不能冒领纠错。

已有 DesignFirstLessonChecks 覆盖全部布尔组合及旧输入拒绝，不在此重写同类单元测试。B 补充的是 UI 与事件、画面间的实际连接。

## 4. C：首分钟停留读题，专查提示打断

新局第一张出现后，松开鼠标和键盘，不输入、不跳剧情，完整停留 60 秒。至少在 0、10、20、30、45、60 秒取关键帧；有变化时增加取帧。此路径刻意允许现有“桌面安静”条件成立。

逐项记录：月卡／剧情、AI 加入 YY、联系人消息、Windows“桌面背景已更改”、平台通知、开局 toast，以及页面内训练／聊天／查看脑子入口。对每项标明：出现及结束时间、是否遮题、是否夺焦点或锁输入、是否要求做首课以外的事、原卡是否仍可回答。

判定分为两栏，避免把“未遮挡”当成“只做一件事”：

- **操作中断**：必须关弹窗、焦点被自动切走、输入被剧情占用、题目／按钮被遮盖，任一项即本栏 FAIL。
- **目标分散**：首课观察窗内自动提示去训练、聊天等额外目标，记本栏 FAIL；静态可选入口单列风险与截图，不能仅凭存在就谎称已发生操作中断。

不得把“正确的剧情顺序”“通知频率受限”或“通用广告静默”视为首课免打断的证明。即便全程不答题，也不得人工屏蔽剧情后重跑出一个 PASS。

## 5. D：快速四卡与输入／布局复测

- **快速四卡**：新局正常答到至少四个有效教学样本且仍在 t0+60 秒内。保持标注页，核对“带它去训练”是否提前成为主要下一步。该用例区分“第一张卡专注”和“完整第一分钟专注”，不要求新增训练功能。
- **键盘**：在标注窗口为最前、无文本输入焦点时，以数字 1／2 各完成一条 B 路径，核对与对应按钮一致。随后在其他窗口输入文字／数字，确认教学卡没有被误答；按键负例只在隔离场景执行。
- **正常连续点击**：等下一卡可见后再次点击，允许下一卡被正常消费。旧卡 ID 的重复输入拒绝由已有检查验证；不能错误要求“任何双击都只结算一次”，因为第二次点击可能属于新卡。
- **宽／窄与中／英**：1920×1080 默认、1280×720 默认，各用中文／英文复测 A 的关键步骤。记录窗口实际宽度，特别观察卡片区域宽度 730 附近布局切换、猜测／按钮／两行反馈是否截断、壁纸是否被默认窗口完全挡住。若被挡住记视觉失败，移动窗口后的截图只附作诊断。
- **减少特效**：另开隔离运行检查 reduceFx=true 时仍有文字确认。记录闪光策略；未定义的无闪策略交整合负责人裁定，不把此选项的结果混入默认特效验收。

## 6. 收尾与证据包

保存：完整录像、点击前／结算／壁纸峰值／回落／下一卡截图、只读事件记录、原始观察 CSV、源码基线、帧率和输入条件。实际执行结束后再次核对依赖 SHA256；过程中发生代码重载或基线变化的受影响用例记 INCONCLUSIVE 并复测。

本条完成条件须同时满足：主聊天实际编译和既有检查完成、自然 A 与停留 C／快速四卡 D 的完整 60 秒记录、B 的真实纠正及误判负例、视觉证据可确认壁纸而非伴随格子亮起。任一缺失均不得把第 13 行或全局策划标记完成。
