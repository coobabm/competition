## 结论

核心接口已有正确的旧卡拒绝，不应再加重复结算逻辑。页面输入仍有两处静态可证的遗漏，交付 `changes.patch`，待整合负责人审阅应用；本任务不是生产修复完成或视觉验收通过。

1. `XgLabelPage.cs:187–188` 的鼠标回调只传 bool；`OnAnswer`（原 355 行）从当前页面重新取卡和猜测。首次成功/失败作答都在原 454 行同步 `Refresh()`。在同一帧继续发生另一输入时，显示 ID 已成为新卡，现有 ID 比较允许第二次结算，即使新卡尚未经过渲染。`XgLabelPage.Spider.cs:172–173` 的数字键也走同一按钮回调；一帧内数字键与鼠标/Submit 是具体触发组合（数字 1/2 本身已有 else-if，不能声称两个数字键必定同时结算）。
2. 左键在 A 卡按下，按住期间模型/超时/其他输入换到 B 卡并刷新，再在同一按钮松开：按钮回调没有 A 卡的身份；当前页面检查的是 B 对 B，随后会提交 B。核心 API 即使正确拒绝旧 ID，也无法识别调用者已经错误改用 B 的 ID。

## 无需更改的现有实现

- `XgSim.Teaching.cs:46–55`：`TryEvaluateTeachingGuess` 在 `Answer` 前校验当前卡 ID 和显示猜测；复核卡也先拒绝。重复传入 A 的 ID 会返回 false，不调用结算或 `LessonTaught`。
- `XgSim.cs:1385–1447`：一次 `Answer` 的奖励/扣费、学习与计数完成后，`NewCard` 换卡；`NewCard`（1281 行）替换该桌旧卡。没有证据需要改核心学习规则。
- `XgLabelPage.cs:357–373`：尚未刷新时提交旧卡，或当前猜测已经变化时，已有 `Refresh(); return;`；应保留。
- `DesignFirstLessonChecks.cs` 已覆盖核心接口重复旧 ID 和预测过期。但重复检查直接传旧 ID，没有经过页面已刷新后的回调，所以不能据此宣称上述 UI 边界已覆盖。

## 补丁内容与接口

- 修改 `Assets/LingGuangV05/XingGuang/Desktop/XgLabelPage.cs`：记录教学卡/猜测首次展示的帧；当帧提交只刷新并返回。普通 Refresh 不重新计帧，因此不会使持续刷新的页面永远不能作答。鼠标按下时保存显示实例、模式、桌、卡 ID、猜测和教学语义；松开后若任一教学上下文不符，刷新并拒绝。按下时尚未渲染的新教学卡也不会在晚一帧松开后被误接受。
- 修改 `Assets/LingGuangV05/XingGuang/Desktop/XgLabelPage.Spider.cs`：数字键直接调用同一 `OnAnswer` 校验，保留现有窗口/输入框/按钮可用性条件。
- 新增 `Assets/LingGuangV05/XingGuang/Desktop/XgLessonAnswerInput.cs`：独立输入组件在 PointerDown 捕获一次 Action，PointerClick 消耗一次，支持 Submit，禁用时清理。保留原 Button 的视觉/导航；原 Button 不再注册答案回调，避免双重派发。新文件完整内容另存为交付目录内同名 C# 文件。
- 辅助组件用 `Bind(Button, Func<Action>)` 接入，不增加模型、钱包、存档或壁纸依赖；Unity 整合时由编辑器生成 `.meta`。
- 新呈现后的下一帧可以正常开始下一题；没有添加时间冷却。跨帧看到 B 后重新按下属于新的 B 输入，不按“重复 A”丢弃。
