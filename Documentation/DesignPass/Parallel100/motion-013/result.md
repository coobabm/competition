主聊天统一运行时：

1. 在隔离验证副本导入上述文件并完成 Unity 编译。建立无根对象的空场景；不要打开正式启动场景或玩家数据流程。脚本不会自行进入 Play，不构造控制器、页面业务或存档接口。
2. 手动进入 Play，选择 AI 页实际传给 `XingGuangView.Build` 的 TMP_FontAsset。运行菜单 `Tools > Design Pass > Motion 013 > Capture Dark Button Frames`。缺少字体、不在交互式 Play、场景非空、存在已加载的 MonoBehaviour（包括非激活对象）时会拒绝执行。若项目自动引导脚本使空场景不成立，应由整合负责人使用隔离验证工程，不放宽到真实存档场景。
3. Game 视图固定至少 1024×768，建议分别固定 1280×800 与 1920×1080 各跑一次；保持 Game 视图可见/有焦点，菜单调用后返回 Game 视图。不要在捕获中改变窗口大小或暂停。WaitForEndOfFrame 在切至 Scene 视图时可能停住，脚本不支持 batchmode。
4. 每轮 12 个用例：Canvas scale .75/1/1.25 × mouse/reduced/rapid/submit。每例六个按钮含小中文、小英文、星号收藏、选中主按钮、长英文压力样本、人工紧贴 RectMask2D 样本。只使用计数回调，Submit 不调用任何生产业务；人工遮罩不是实际页面结构的断言。
5. 脚本在每个真实帧末从 Game 视图读回按钮区域，先保留像素，动画结束后再编码 PNG。输出到本目录 `captures/<UTC时间>/`；JSON 记录时间、帧号、真实 dt、字体、字体名义像素尺寸、缩放、位移、文字四角到按钮/人工遮罩的距离、背景名义对比度、cull 和疑似缺字信息。它不手动调用 Update，也不重写或重放生产波形。
6. 找到 `CAPTURE_COMPLETE.txt` 才表示所有用例采集完毕。ERROR、缺少完成标记、帧数上限、低帧率提示或缺失压缩/回弹阶段都不能作通过证据。脚本不锁帧率；读回本身会造成开销，因此不足覆盖时应重新采集。每例最大 96 帧，编码前像素约不超过 162 MB（最大 .75/1/1.25 样本中为 900×500 RGB），另有 Unity 开销。

## 必须人工判读的结果

脚本只报告 `CAPTURED_REQUIRES_VISUAL_REVIEW`，不自动宣布视觉通过。以 rest 帧为基线，找 JSON 最小 scale、最大 scale 和末帧对应 PNG：

- 小字号汉字、英文、星号在收缩和回弹时是否仍清楚；有没有缺笔、异常模糊、替代方框。JSON 的 nominalFontPixels 不是字形实际笔画高度，疑似缺字检测也不替代看图。
- `GLYPH_OUTSIDE_BUTTON` 是文字几何越界提示；无 Mask 时可能只是溢出。`CLIP_REVIEW` 应结合真实截图检查；TMP shader 描边/发光不包含在字符几何四角里。先辨别 rest 就溢出的长英文样本，再判断是否由回弹新增或加重，不能把人为窄宽度样本当作生产缺陷。
- 缩放复核预算为普通 ±5%、减少动效 ±2%，位移不超过 1.01 UI 单位；这是保守审查界限，非照抄波形的期望帧。低于阈值也不等于文字视觉清晰。
- 确认末帧复位、业务计数等于样本数、快速重按没有逐次累积收缩。减少动效应明显弱于普通模式。
- 本脚本是生产按钮组件的隔离样本，**不是 AI 应用真实页面或旧强动效的视觉证据**。主聊天还须在不接触真实玩家存档的场景中，使用实际页面、实际字体/父遮罩/窗口缩放，采集普通/选中/窄按钮以及既有强 Knock 的按下、回弹、结果帧，确认旧动效保留。不得据本样本验收所有页面或全局三层原则。
