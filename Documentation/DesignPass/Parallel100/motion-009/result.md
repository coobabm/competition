# motion-009：Label 基准恢复

日期：2026-10-13（Asia/Singapore）。交付状态：确认一处布局期间基准失效，提供候选补丁及验证入口；未应用生产文件。静态编译完成，Unity 运行与视觉验收未执行。

## 结论与已有正确行为

本任务仅核对已授权条目下的 Label 基准恢复，没有读取新的策划正文，也不代表「每个操作至少占两层」或整份文档完成。

- 非默认局部位置、非单位局部缩放：当前实现首次 `Knock` 保存 `localScale` 和 `anchoredPosition`，完成及取消恢复保存值，并未硬编码 `Vector3.one`／`Vector2.zero`。这部分无需重新实现。
- 父级缩放、纯锚点随窗口尺寸变化：局部缩放与锚定偏移不等于世界变换，原实现没有读写父变换或缓存世界坐标，因此这两种情况本身不构成错误。补丁不改窗口默认大小。
- 确认的缺口：动画存活期间，布局将 Label 的锚定位置更新为新基准后，下一次 `Update`、重复 `Knock` 或取消仍使用按下时旧基准，可能覆盖布局结果。现有同步检查未覆盖布局重建。

## 候选变更

`changes.patch` 包含三个目标文件的当前 SHA256 和四行上下文；完整候选在 `candidate/`，只作审阅／静态编译材料，不应整文件覆盖持续更新的生产源码。

1. **XgJuice**：增加默认关闭的 `TrackKnockLayoutChanges`。记录上次自身实际写出的值；在后续动画更新、重复触发、清理之前，逐轴把与自身上次输出不同的外部绝对值采纳为新基准。未被改写的轴保留旧基准。读取实际写后值，避免将自身写入误判成布局变化。不做除法，支持负缩放和零缩放；不改原 Knock 签名、波形、时长、粒子、音效或业务默认语义。

## 接口合同与限制

自动追踪的合同：动画独占临时变形，外部布局写入**绝对静止值**。不得把包含动画偏移的当前值再加一个位移，冒充新基准；也不能让两个独立动画同时争用 Label。原任务记录已要求业务直接动画 Label 时另行明确所有权。

仅凭数值无法识别「外部新基准恰好等于上一帧动画输出」这一写入意图。因此增加明确接口：

```csharp
// 自定义布局掌握实际静止值时，在完成布局写入后、下一次动画更新/取消前调用。
labelPrivateFx.SetKnockRestTransform(label, absoluteLocalScale, absoluteAnchoredPosition);
```

接口只作用于已开启追踪且仍在运行的该目标 Punch；无活跃动画时，直接设置 RectTransform 即可。传入完整静止值，不能从仍带动画变形的其他轴直接拼装。数值比较能修复常规可观测改写，但不宣称自动解决相同数值重写或多写入者意图冲突。若实际自定义布局存在这类场景，需要整合负责人在布局拥有者处接入此接口；当前未发现或臆造其调用位置。

连续每帧布局重建时，布局可能在动画之后覆盖当帧位移；本补丁修复基准恢复，不承诺这种争用下的每帧动效视觉连续性。真实布局视觉仍需主聊天验收。
