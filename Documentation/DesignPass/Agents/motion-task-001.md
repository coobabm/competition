## 实现与覆盖

- `XgUi.Button` 安装继承自 uGUI `Button` 的组件，仍以原 `Button` 类型返回，不改变业务回调及调用次数。
- 左键按下触发文字压缩与微移，再回弹；键盘／手柄通过 EventSystem 的 Submit 提交，在业务回调之前触发相同反馈。按住期间不额外循环，也不在松开时重复播放。
- 保留原背景颜色反馈。通用位移与缩放只作用于非射线目标 `Label`，不改变按钮布局、点击区域或业务使用的按钮本体变换。
- 首次使用才在文字对象上建立私有 `XgJuice`，只调用无需 `Init` 的 `Knock` 路径，不创建粒子层／声音池。独立效果栈不会覆盖或清空宿主对按钮本体的强 `Knock`、飘字或音效。
- 连点复用 `Knock` 已保存的静止变换，不以中途缩放／偏移为新的基准。动画结束后恢复原变换并停用私有效果组件。
- 右键／中键不触发通用手感；`IsActive`、`IsInteractable` 同时检查按钮和父 `CanvasGroup`。禁用、隐藏时立即清理自身效果；宿主不可见／禁用时不启动，进行中的效果在后续帧清理。
- 宿主 `XgJuice.Reduced` 开启时，压缩幅度由 0.045 降到 0.015，去除 1 单位下移，时长由 0.18 秒缩短为 0.12 秒。按未缩放时间运行。

限制与接口边界：

- 通用手感本身只占「手感层」。业务结果变化、飘字、壁纸反应继续由业务负责，本项未声称全面核验第二层。
- 手写按钮、`XgHold` 独立业务行为、滑块、拖拽、卡片及壁纸操作不在本次覆盖内。
- 直接调用 `button.onClick.Invoke()` 属于程序性业务调用，不追加玩家按压动画；键盘按键是否映射为 Submit 由现有 EventSystem 配置决定，未添加全局按键监听。
- 通用文字反馈与按钮本体业务反馈可同时出现；这是有意的目标隔离，具体视觉力度仍需实景验收。若业务今后要直接动画 `Label`，应先明确其动画所有权，避免共用同一目标。
- 私有效果组件每个已使用按钮至多一个。`XgJuice` 自带的集合会随首次使用分配；本次不改动效引擎，真实界面的分配和帧耗仍待观察。
