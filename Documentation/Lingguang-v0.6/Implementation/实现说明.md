# 《灵光一闪》里程碑 1 实现说明

对应规格 v0.6（2026-10-01）。本里程碑只做逻辑：Model、Simulator、配置，以及验收用例 T01–T21、T23，不含任何画面。T22（流光漂远）属于第 12 节 P1，流光实现时再加。

## 1. 怎么放进 Unity 工程

1. 用 Unity 6 LTS 新建（或打开）2D URP 工程。
2. 把压缩包里的 `Assets/Lingguang` 整个文件夹拖进工程的 `Assets/` 下。Unity 会自动生成 `.meta` 文件，并编译出三个程序集：
   - `Lingguang.Core`：纯 C#，不引用 UnityEngine（规格第 2 节的 Model + Simulator）；
   - `Lingguang.UnityBridge`：ScriptableObject 配置资源、热重载组件；
   - `Lingguang.Core.Tests`：EditMode 单元测试。
3. 跑测试：菜单 `Window → General → Test Runner` → 选 `EditMode` 页 → `Run All`。应当看到 59 个测试全部变绿：T01–T17 在 `AcceptanceTests`，T18–T21、T23 与 v0.6 的默认值、微弱连接在 `AcceptanceV05Tests`，v0.4/v0.5 规则的回归在 `RuleV05Tests`，与 Python 参考模型的逐拍对照在 `ReferenceConsistencyTests`。`EmergenceBench` 是调参用的涌现基准，标为 Explicit，Run All 不会跑，需要在 Test Runner 里选中单独运行。
   Unity 6 默认已经装了 Test Framework 包；如果 Test Runner 菜单不存在，到 `Window → Package Manager` 搜索 “Test Framework” 安装。
4. 建配置资源：在 Project 窗口右键 `Create → 灵光一闪 → 游戏配置 GameConfig`，以及 `Create → 灵光一闪 → 棋盘地图 BoardLayout`。新建的资源已经填好规格默认值。

`DotnetHarness/` 文件夹不要放进 Unity：它只用于在命令行脱离 Unity 跑同一批测试（我这边就是用它验证的）：

```
cd DotnetHarness/Tests
dotnet test
```

```

    Rules/      BoardRules（光丝几何、放置/旋转/移动）  EffectQuery（把生效的效果翻译成规则修正）
                PatternRules（回路型与新鲜度）  Lifecycle（轮与阶段：结算、废退、修剪、记忆、沉淀、本能、老年、拾物点）
    Sim/        Simulator（传播与涟漪）  SimEvent（事件流）
    GameSession.cs   一局的入口：放置、旋转、移动、确认、结束本轮、撤销、试运行、热重载
  Runtime/UnityBridge/
    GameConfigAsset   BoardLayoutAsset   ConfigHotReloader
  Tests/EditMode/
    TestKit   AcceptanceTests（T01–T17）   AcceptanceV05Tests（T18–T21、T23）   RuleV05Tests   ExtraTests
    ReferenceConsistencyTests + ReferenceCases.txt（与 sim.py 逐拍对照）   EmergenceBench（真实棋盘上的涌现基准）
```

表现层（里程碑 2）只需要做两件事：调用 `GameSession` 的方法，然后逐个播放返回的 `SimResult.Events`。不要在表现层里写任何规则判断。

## 3. 地图怎么改

地图是数据，不是代码。打开 `BoardLayout` 资源后可以改这些内容：

- **Rows**：每行一个字符串，格子之间用空格分隔，`.` 表示无格子，字母表示区域；
- **Regions**：区域字母、名称、解锁阶段；
- **MidlineLeftColumn**：中线所在列（设为 -1 关闭中线）；**MidlineBridges**：窄桥所在行和开放阶段；
- **SealedRegions / SealedRegionGaps**：外侧沟包住哪些区域、缺口在哪；**ExtraFixedGrooves**：额外的固定沟；
- **LighthouseAnchors**：灯塔锚点；**SecondaryGroovesMin/Max**：次级沟数量。

改完后右键资源标题选“校验地图”，控制台会打印格子数、各阶段是否连通，以及 100 个种子里有几个能生成次级沟。把这个资源拖到 `GameConfig` 的 `LayoutOverride` 上即可生效。

## 4. 热重载

在场景里放一个 `ConfigHotReloader` 组件，把 `GameConfig` 资源拖进去，然后订阅它的 `Reloaded` 事件，在回调里调用 `session.ApplyConfig(cfg, out reason)`：

- 地图形状没变时，直接换用新数值继续本局，从下一次确认起生效（这一步会清空撤销栈）；
- 地图形状变了时返回 false，需要用新配置重新开局。

配置有两个来源：Inspector 里改 `GameConfig` 资源，或者改写 `StreamingAssets/lingguang_config.json`。后者在 `GameConfig` 资源上右键“导出 JSON 到 StreamingAssets”即可生成，打包后试玩时也能直接改这个文件调参。

## 5. 事件流（给表现层）

| 事件 | 主要字段 | 说明 |
|---|---|---|
| LighthouseShine | Centers=锚点, Cells=覆盖格, Radius, Amount, GlowId | 第 0 拍最先发生，灯塔从棋盘外照进来；老年 GlowId=被照亮的那段记忆的成员 |
| Fire | Cell, GlowId, Amount=光量, Beat, Perturb=本轮第几次闪 | 记忆的每个成员各发一个；Perturb ≥ 2 表示再次闪（回荡） |
| Deliver | From→Cell, SourceGlowId→GlowId, Amount, SendBeat, Kind, Perturb | Kind 取值：Edge 光丝 / Lost 空格 / Ripple 涟漪 / WeakLink 微弱连接 / Lighthouse 灯塔；每个 Edge 投递播放“扰动”，Perturb 为本次扰动增量 |
| Conduct | From→Cell, Amount=导通后次数 | 播放“稳定”；每次导通会在 Cell 产生一个涟漪 |
| EdgeLevelUp | From→Cell, Level（0 新生 1 加粗 2 髓鞘化） | 也用于窄桥惩罚解除 |
| Lost | Cell | 电送到空格（v0.4 起不再有 Wasted：送到已闪灵光的电照样累积） |
| BeatEnd | Cells, Values | 每拍漏电之后各灵光（记忆按一个）的电量，用于电量环与调试面板 |
| RippleSpawn / RippleMerge / RippleApply | GroupId, Centers, Cells, Radius, Count | Spawn 每个中心一个；Merge 只在数量 ≥2 时发；Apply 在下一拍发 |
| RippleConduct | Cell | 灵光被涟漪或微弱连接推到阈值而闪 |
| PickupCollected | Cell, ItemId | 拾物点被领取 |
| PatternRecognized | Pattern, LightDelta, MultDelta, Count=新鲜度连续次数 | 每次确认最多一个 |
| ScoreDelta | LightDelta, MultDelta, Source（fire / converge / pattern） | 计分栏跳动用 |
| ChainEnd | Beat, Error | Error=true 表示超过 200 拍的安全上限 |

事件已经按播放顺序排好；同一拍内的事件可以同时播放。无依漂走不在事件流里，而在本轮结算结果 `RoundSettlement.DriftedGlowIds / DriftedCells` 中，结算动画时播放。

## 6. 规格未写明处的实现决定

除第 1 条外，其余各条均已与 kk 确认。改动时请同步更新这份说明和对应的测试。

1. **灯塔（v0.3 改为“从棋盘外照进来的初始光源”）**：
   - 时机：本轮第一次确认的第 0 拍，最先发生，然后起点才闪。
   - 效果：它送来的电和起点的电在同一拍累加，可以把灵光推到阈值；这样闪的灵光不加导通、不产生涟漪。
   - 范围：灯塔在棋盘之外，光从锚点格进入，所以覆盖“距锚点 ≤ R − 1”的格子。各阶段实际覆盖为：婴儿 2 圈、童年和青春期 1 圈、成年和中年只照锚点两格。配置项 `LighthouseFromOutside` 设为 false 即可恢复“距锚点 ≤ R”。
   - 老年（kk 提出）：灯塔只照一格——一生中记忆最深刻的地方。照到记忆的一个成员，整个记忆都收到电（记忆阈值 2，所以每轮第一次确认时它会在第 0 拍整体闪一次）。
     - “最深刻”的判定：整局被触发次数最多的记忆；次数相同比折叠时的组内导通和；再相同取更早形成的。
     - 进入老年时选定，之后一直照着它；那里的格子因老年衰退失效后，下一轮改照次深的记忆。
     - 一生没有形成记忆时，照进出光丝导通次数之和最大的灵光；连这个也没有就不照。
     - 由阶段配置 `LighthouseFocus` 控制（None / DeepestMemory / Character）。Character 预留给“与人物的链接”，人物系统接入前等同 DeepestMemory。
   - 其他：两座灯塔不叠加；本次的起点不再额外收灯塔的电。
2. **涟漪**：每次导通各产生一个涟漪，所以汇聚收到 3 条导通，会在同一格生成 3 个中心，合并成半径 2 的群。`RippleCharge = 0` 等于关闭涟漪。
3. **发散**：按“该锥体因导通点亮了几个灵光”计算，不严格限定在下一拍；否则光丝髓鞘化或在“培训班”关口下延迟为 0 时，发散永远无法触发。
4. **记忆（原组块）**：组内导通次数之和为 0 时不折叠；记忆成员暂时不能移动（规则待定），但可以旋转（消耗可塑度）。
5. **沉淀区域（v0.3 新增）**：
   - 阶段结算时先折叠记忆，再让该阶段解锁的区域进入沉淀，可塑度初始为 3。
   - 消耗：区域内任一灵光（含记忆成员）旋转或移动扣 1；从别的区域移入沉淀区域，同样要付目标区域的可塑度；记忆每被触发一次扣 1。
   - 回合变化：区域内有灵光闪过的轮次计为“被触发”，连续 3 轮被触发归零，连续 2 轮未被触发 +1。
   - 可塑度为 0 时，区域内的灵光不能旋转、移动。在沉淀区域里放置新灵光不受限制。
   - 记忆本身不再单独记可塑度，统一用所在区域的可塑度。
6. **新鲜度**：只打折倍率加成，不影响光量加成；从成年开始计算。
7. **起点**：允许一次确认选多个起点。
8. **连锁长度 L**：取有灵光闪光的最大拍数；只有涟漪而没有闪光的拍不算。
9. **其他小决定**：
   - 随机数：用自带的 SplitMix64，没用 System.Random，因为撤销和试运行需要把随机状态一起拷贝。
   - 微弱连接：跨轮保留，但每轮结算减弱 1、强度 ≥ 3 才传脉冲（见第 7 节）；灵光被移动或漂走时删除它的全部微弱连接。
   - 老年阶段：失效格先从 F 区抽，F 区用完再抽 T 区；额外延迟对记忆发出的光丝不生效。
   - 关口“模仿”：上一轮和本轮都没有回路型时，算作“相同”。
   - “分离”关口出现的条件由 `RunOptions.SeparationUnlocked` 控制；`GameSession.ReachedChildhood` 供局外进度保存这个解锁。

## 7. v0.4/v0.5 规则的实现与测试结论

### 已实现
- 漏电 `LeakPerBeat`、疲劳 `RefireThresholdStep`（同一拍最多闪一次）、扰动 `PerturbStep / PerturbCap`、无依 `RootingRounds / UnanchoredRoundsToDrift`。
- 记忆再次触发遵循阈值抬升；记忆每触发一次扣所在沉淀区域可塑度 1。
- `SimResult.MaxFiresPerUnit / Reverberated` 记录回荡。

### 规格 v0.6 采纳的三处默认值
规格 v0.6 采纳了开发会话基于基准测试提出的三处默认值；v0.4/v0.5 的写法仍可通过配置打开，用于对比：

| 配置项 | v0.6（当前默认） | 设为另一值即旧写法 |
|---|---|---|
| `LeakStoredCharge` | 否：只有本次连锁中收到过电的灵光才流失 | 是：所有电每拍都流失，T05 不成立 |
| `RippleReachesFired` | 否：涟漪只给本轮还没闪过的灵光 | 是：回荡从第 1 轮就出现，“回荡是学会的”不通过 |
| `WeakLinkMinStrength` / `WeakLinkDecayPerRound` / `WeakLinkToFiredPartner` | 3 / 1 / 否：微弱连接遵守规则三 | 1 / 0 / 是：每轮平均闪光约 550 次，涌现检查只过 1 项 |

微弱连接“另一方本轮还没闪过”在送出和到达时各判断一次，所以同一拍一起闪的两个灵光不会因先后顺序互相送脉冲。

真实棋盘基准（`EmergenceBench_Grid`，60 个随机网络各 30 轮）：

| 涟漪 | 微弱连接 | 涌现检查 | 每轮平均闪光 |
|---|---|---|---|
| 给已闪 | 关 | 5/6（回荡不是学会的） | 12.9 |
| 给已闪 | v0.5 写法 | 1/6 | 549.8 |
| 只给未闪 | v0.5 写法 | 1/6 | 384.2 |
| 只给未闪 | 关 | 6/6 | 9.7 |
| 只给未闪（v0.6） | 遵守规则三（v0.6） | 6/6 | 12.7 |

完整规则（灯塔、窄桥惩罚全开）在 v0.6 默认值下也是 6/6：每轮平均闪光约 13 次，单个灵光一轮最多闪 4 次，最长 11 拍。

### 跨实现一致性（T23）
`board_ref.py` 把 `sim.py` 放到真实棋盘上，生成 24 个布局、480 轮、2823 次闪光（108 轮有回荡）的用例；C# 的每一次闪光与每条光丝的导通次数都与之一致。对照中发现并修复了一个顺序依赖：同一批要闪的灵光现在先全部记完导通再一起闪，结果不再取决于灵光编号。

### 由规则推出的现象（供设计记录）
- 新生光丝组成的两点环不回荡，环要先加粗（与“回荡是学会的”一致）；完全髓鞘化的两点环也不回荡：回传的电当拍到达，而同一拍内不能再闪，电停在阈值上。
- T20 中第二次经过同一条新生光丝时，下游已疲劳，扰动后的 3 仍不够让它再闪：这次传电只有扰动、没有稳定。

### 规格里需要澄清的小处
- 第 5 节第 6 步字面上在最后一拍结束后也流失一次，但这样 T05（“在连锁最后一拍让锥体积 2……第二次确认时闪”）不成立。实现按 T05：连锁停下时剩下的电原样留到下一次确认（`LeakAfterLastBeat = false`）。建议规格 v0.7 在第 6 步补一句“最后一拍不流失”。
- 无依的扎根期按“放下的那一轮的结算也算第 1 轮”计，第 4 轮结算起才开始计无依。

## 8. 尚未实现（按规格里程碑排在后面）

- **物件、药品**：效果系统的数据格式和全部操作枚举已经定义好，但目前只实现了关口用到的那些操作（里程碑 4 再接物件和药品）。
- **商店**：目前只计算金币，没有商店流程。
- **v0.3 的新操作方式**：滚轮在灵光上旋转、在背景上缩放；拖拽背景平移；点击记忆展开或收拢（只改显示）；双击背景复位视角。这些都属于表现层，在里程碑 2 实现，逻辑层不需要改动。
- **流光（第 12 节，P1）与 T22**：核心闭环稳定后再做。老年灯塔的 `LighthouseFocus.Character` 已预留。
- **光敏安全（第 10 节，必须满足）**：属于表现层，在里程碑 2–3 实现。事件流已经提供需要的信息：每拍的 Fire 数量（用于合并或降亮）、Fire.Perturb ≥ 2（回荡）、汇聚的 ScoreDelta（source = converge）。表现层要做的是：大面积亮度变化每秒不超过 3 次；不用饱和红色闪烁；密集场景合并或降亮；提供“降低闪烁”选项（减弱闪烁、关闭震屏）；启动时显示光敏提示。
- **数值手感**：用脚本跑完 18 轮的结果看，中后期得分涨得很慢。这属于里程碑 5 的调参内容。
