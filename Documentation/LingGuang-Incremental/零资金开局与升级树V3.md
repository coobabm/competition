# 灵光：零资金开局与增量升级树 V3

日期：2026-10-03。适用：Main 场景的 LingGuangV05 / XingGuang，不是旧 LingGuang 棋盘。

## 0. 状态与边界

用户明确：初始钱包 ¥0；第一项技能提升人工标注金额；后续技能符合增量游戏的成长规律。

本次已实现：
- GameState.money / GameConfig.starterMoney 默认 0；保留赠送的一张显卡和一个机箱，不清空旧存档。
- 首节点 `manual_pay`，¥10，人工答对报酬 ×2；覆盖标注台与 YY 人工答题，不改变自动答题报酬。
- 与原连击、难度、高能牌乘算；答错不发钱、不多给样本；节点不可重复购买。
- 打开技能树首先聚焦该节点，包括钱不够时；标注台单价同步显示。

**下文其余节点与价格是待实现的设计，不是当前功能清单。** 本稿补充现有《训练动作与技能树设计.md》，不推翻一键训练、评估纪录奖、分阶段自动化与共享钱包。数值是首轮调参候选，不声称已经跑过完整平衡仿真。

## 1. 增量规则：钱用来改变产出结构，不只堆百分比

参考 Anthony Pecorella / Kongregate 的一手文章《The Math of Idle Games, Part I》（Game Developer，2016-10-13）：指数成本、较缓的基础产出增长、离散倍率里程碑和跨生产线选择，组成成本与收益的交替。作者也指出，新生产线若永久压倒旧线，会消除有意义的选择。[S1]

本项目的设计取舍：
1. 只有 ¥ 是升级消费货币。论文、正确标注数、最高模型分是解锁条件，不再新增金币/水晶/科研点三套钱包。
2. 可重复数值升级采用递增价格；能力节点只买一次，改变操作方式。
3. 用少量里程碑产生明显跃升；不要所有技能都是 +5%。
4. 自动化替代已掌握的重复劳动，但不自动解出新标注题、不无条件给满分。
5. 手动早期负责生存，中期负责冲纪录，后期负责可选的抽检增益；不让挂机玩家必须连点才能保住已有收益。
6. 不要求买全所有支线才能推进；每阶段至少有两个值得考虑的投入方向。
7. 第一章暂不加转生。先证明单轮经济有内容；后续章节若需要研究继承，再单独设计，不能用清空玩家进度掩盖枯燥。

## 2. 零资金开局必须可恢复

- 钱包 0，一张赠送显卡、一个机箱、免费初始题库和免费安装流程。
- 人工标注无需买节点，不耗付费道具。停电也允许人工操作；答对得到的钱可用于恢复供电。
- 升级不能让余额为负；买不起明确显示还差多少钱。
- 不为满足本设计重置用户当前档。仅新游戏/明确的重新开始采用零资金默认值。
- 日常费用必须保留；首轮低频玩家到第一次电费前应有合理收入。不能靠一笔隐藏赠款回到旧的650开局。
- 显示下一张预计基础报酬、连击倍率、待付电费。实际支付额仍由 Core 的一次结算决定。

### 首次反馈

初始一级普通题基础 ¥0.50。当前连击每次 +5%，最高 ×2。
无答错/超时、无高能牌、均为一级题时，连续答对15张共获得 ¥10.50，可买第一次加薪；完全不保连击则约20张。
购买后基础价 ¥1.00，第一张带1.05连击为 ¥1.05。界面同时给出旧价→新价，不能只飘“解锁成功”。
“每题2–4秒”只是节奏假设：第一次升级约30–80秒，必须以真实玩家输入速度验证，而非假设玩家每秒点两次阅读题。

## 3. 总体树形：一个起点，四条互相补充的路线

```
¥0 → 免费人工标注 → 人工标注加薪 I（¥10）
                       │
       ┌───────────────┼────────────────┬───────────────┐
       │               │                │               │
   人工效率         模型训练          自动化          商业与硬件
   熟练标注         学习率/层宽       按住训练        第一份订单
   连击容错         动量/稳态         定时训练        订单服务升级
   第10级跃升       更多数据          自动标注        显卡与机箱
   高级题专精       新架构            后台/早停       节电与持续经营
       └─────────────── 更高验证成绩 → 新任务 → 再投资 ───────────┘
```

布局目标：起点位于视口左上或中央第一屏；左侧人工、中央模型、右侧自动化，商业节点指向现有“订单/寻宝/家庭”。可预览下一层，未到阶段的深层节点折叠。不要初次打开就给70个灰色技术名词。

## 4. 人工线：先感觉明显变强，再逐渐让出重复劳动

| 节点 | 成本 | 条件 | 效果 |
|---|---:|---|---|
| 人工标注加薪 I | ¥10 | 无 | 人工基础收益×2；本次已实现 |
| 熟练标注 II–X | 见公式 | I；II需累计20次人工正确，V需100次，X需500次 | 每级增加初始基础收益的50%；第X级额外×2 |
| 连击容错 | ¥40 | I，累计30次人工正确 | 人工标注的连击时间窗+1秒，不延長限时牌本身计时 |
| 专业标注 | ¥240 | 曾答对三级题 | 三级及以上人工答题收益×1.5；不影响一二级题和自动答题 |
| 人工抽检 | ¥2,400 | 已有一份订单、专业标注 | 对订单所属数据集连续人工答对3次，该订单收益+20%，持续60秒；刷新不叠加，无操作不扣基础收入 |

可重复升级的定义，L=已拥有的加薪等级，首章上限10：

```
下一次价格 = ceil(10 × 1.8^L)       // L=0购买第I级，价格10
人工基础倍率 M(0)=1
M(L)=(2 + 0.5×(L−1)) × (L≥10 ? 2 : 1), L≥1
人工报酬 = 0.5 × 难度倍率 × M(L) × 连击倍率 × 高能倍率 × 专业标注倍率
```

| 买到等级 | 本次价格 | 一级普通题基础价（不含连击） |
|---|---:|---:|
| I | 10 | 1.00 |
| II | 18 | 1.25 |
| III | 33 | 1.50 |
| V | 105 | 2.00 |
| X | 1,984 | 6.50 |

规则：不额外增加样本，不改变判断对错；事件一次性奖金（如斗图胜利）不跟着全局倍增。更难题目必须按真实阅读时间比较“¥/有效分钟”和样本价值，避免只刷最简单数字成为唯一最优解。

第X级需要累计500次人工正确，是长期主动路线的可选终点，不是章节通关或自动化的必需前置。如果实测过于机械，先降低门槛，不增加“每日强制标注”任务。

## 5. 模型线：解决当前瓶颈，而非层数越多越好

| 节点 | 成本候选 | 条件 | 选择理由/效果 |
|---|---:|---|---|
| 学习率旋钮（各线） | ¥40 | 本线完成首次评估 | 开放现有学习率选择；先体验固定参数，再给风险选项 |
| 动量 SGD | ¥80 | 任意首次评估 | 沿用×1.3速度和稳定性提升 |
| 第3层/第2层 | 视觉¥80 / 序列¥120 | 本线已有12样本 | 增大容量，但提高显存/过拟合压力 |
| 宽32/64 | ¥150 / ¥450 | 上一档宽度；64额外需本线1篇论文 | 延续现有宽度递进，显存不足不可假装“立刻生效” |
| 梯度裁剪 | ¥120 | 序列首次评估 | 降低不稳定性；不要求先炸一次才能买 |
| Dropout | ¥250 | 任意模型达到B级 | 沿用过拟合惩罚×0.5，不直接凭空加准确率 |
| 首个完整基础数据包 | ¥300 | 对应题库累计50条有效样本 | 买数据解决样本瓶颈；手工路线仍可继续 |
| 数据增强 | ¥600 | 视觉1篇论文 | 沿用视觉有效数据量×3，只对曲线样本项生效 |
| RMSProp | ¥900 | 动量，本线最高模型分600 | 沿用×1.6速度与较高稳定性；不与SGD速度再次连乘 |
| BatchNorm | ¥1,800 | 梯度裁剪，累计3篇论文 | 沿用速度/稳定性/可用深度改善 |
| Adam | ¥4,000 | RMSProp，累计6篇论文 | 沿用×2速度；是替换优化器，不是所有优化器乘一起 |
| cuDNN | ¥6,000 | Adam，已有2份订单 | 沿用全训练×1.5；算力仍受电力/热限制 |
| 迁移学习 | ¥8,000 | 至少完成两个不同数据集的评估纪录 | 沿用切换架构/数据时保留60%进度，减少重复开荒 |

架构路线保留原主题与大体价位：
- 视觉：LeNet免费 → AlexNet ¥500/本线1论文 → VGG ¥2,000/3论文 → GoogLeNet ¥6,000/6论文 **或** ResNet ¥15,000/10论文。
- 序列：RNN免费 → LSTM ¥500/本线1论文 → GRU ¥1,500/3论文 **或** Seq2Seq ¥4,000/5论文 → Attention ¥12,000/10论文。
- 分支不是永久互斥。GoogLeNet偏参数效率，ResNet偏深度上限；GRU偏效率，Seq2Seq开放翻译任务，不能只按售价排成“贵的一定全部更好”。
- 难度解锁必须可达：前置论文成绩需用前一档架构+可用数据实际跑得到；禁止“解锁LSTM需要论文，而论文又必须有LSTM”的环。

## 6. 自动化线：依次解放动作，不一下子挂机到底

| 节点 | 成本候选 | 条件 | 自动接管的工作 |
|---|---:|---|---|
| 训练脚本 run.sh | ¥30 | 手动训练过1轮 | 按住训练连续跑，不负责判断题卡 |
| 定时任务 crontab | ¥180 | 手动训练20轮、完成首次评估、run.sh | 窗口开着每3秒自动跑一轮，沿用半强度，不造连击 |
| 后台守护进程 | ¥900 | crontab，至少1份订单 | 关闭窗口仍训练；离线按同一资源规则结算，上限先保留30分钟 |
| 自动评估/早停 | ¥2,500 | 后台守护，已有3次评估纪录 | 每轮自动评估；连续3次无改善暂停当前训练，保存最优结果并提示瓶颈 |
| AutoML 调度 | ¥12,000 | 自动评估，2个数据集达到A级 | 在已购买的架构/参数/数据范围内选下一项工作，不自动花钱，不自动购买整树 |

早停目前代码的 `autockpt` 主要是自动保存，不等于真的停止训练；未来实现必须把“暂停条件/恢复条件/用户手动继续”做实，不能只改技能名。

### 自动标注是另一种生产者，不等于自动训练

- 对应数据集已部署准确率≥60%才可买；未达到时显示“还差多少成绩”，不要显示一个永远灰的按钮。
- 每个题库单独购买，首级¥30，后续 `ceil(30×1.55^n)`，n为当前等级；首章最多10级。
- 每级沿用0.3题/秒，实际收入乘已保存准确率；只有模拟答对才增加钱和样本。
- 自动收益不继承人工加薪、人工连击和高能牌倍率，否则主动线会被动把挂机收益放大失控。
- 第5/10级该题库速率各额外×2（累计×4）；这属于候选跃升，需要同时检查算力共享与样本成长速度。
- 停电时生产暂停；不会扣掉已赚的钱和已学样本。多路任务必须共享有限算力，不能每个题库都按整张GPU计算。

基准示例：准确率80%、一级题¥0.5、0.3题/秒，初级自动标注毛收益约¥0.12/秒，首级¥30的静态回本约250秒。它还产样本，因此不能只按现金衡量价值；这是公式估算，不是真实游玩成绩。

## 7. 商业与硬件线：把成绩转换成可持续现金流

- 订单解锁继续依赖该数据集的已保存验证成绩；不是付钱直接买一个自动通过考试的模型。
- 第一份订单不收新解锁费，达到门槛签约即可获得当前首付款和基础收益。
- 服务等级：每份已签订单增加最多5级，`成本=ceil(60×订单基础每秒收益×1.8^n)`；每级给该订单基础收益+25%，第5级额外×2。准确率带来的现有效率加成单独应用。
- 第一级服务升级的理想毛回本约240秒；叠加电费后用净收益重算。不要把一次性首付款当作每秒收入。
- 显卡¥450和机箱¥2,000先保留在寻宝，不在技能树再卖一次同样的硬件。技能树只显示瓶颈和跳转入口。
- 散热/节电放在家庭的后续升级，不先发明新的温度货币。候选“训练省电”¥600，训练附加功耗−20%，不降低机器原有基础功耗。
- 不建立“自动签约=自动收首付款多次”的漏洞；重复签约/重复评估/离线重载全部幂等。

## 8. 必须先统一的旧规则：否则新树的平衡是假象

代码检查发现的现状（不是新增需求的完成声明）：

1. **家庭旧分类接活仍可在核对3张邮件后开启**，收入走 ChapterOneSim；新灵光订单走 XgSim，两套都进同一个钱包。只改技能树价格无法控制总产出。建议新版把家庭作为收支面板，旧任务迁移为一份显式新订单；保留老存档已获权利，先停止新档重复开启旧收入路径。
2. **每次训练按0.6 GPU秒计电费，而当前离线/双线自动化另有自己的时钟。** 多个生产者必须按实际分配的算力统一结算，不得训练和自动标注各拿一份完整算力还只付一份成本。
3. **评估是一次性纪录收入，不是无限生产者。** 保持差分纪录奖励，首次评级奖只领一次，避免反复切数据/加载存档刷钱。
4. **人工标注最简单的题和最难的题耗时不同。** 用实测正确率与阅读耗时来调各台单价；现有难度倍率本身不能证明难题值得做。
5. **论文是成绩门槛，不是第二个可花钱包。** 老研究表中的citation cost等遗留字段不能误用于新树购买。

以上是下一轮完整树实现的前置事项，本次不偷偷关掉现有收入或改写存档。

## 9. 节奏与验收目标（设计目标，不是实测结论）

| 阶段 | 目标窗口 | 玩家体验 | 首要验证 |
|---|---|---|---|
| 手工起步 | 0–2分钟 | 自己赚到钱，首次加薪明显 | 0元可完成，无倒贴/无付费解锁题库 |
| 第一次模型进步 | 2–8分钟 | 训练→评估奖金，选择手工升级或省操作 | 不因样本门槛/电费形成死锁 |
| 半自动 | 8–20分钟 | 减少重复按键，开始养一条生产线 | 等待不只是挂机；另一路仍可操作 |
| 后台与分支 | 20–45分钟 | 放手让系统跑，主动操作用于冲刺 | 主动/挂机都有可持续进展 |
| 第一章研究终点 | 45–90分钟 | 至少两条可行路线，形成明显专长 | 不要求买完整棵树，未验证跨章平衡 |

平衡指标：
- 对每个升级记录现金回本 `C/ΔR_net`、非现金收益（样本/解锁任务）、距离下个能力跃迁的时间。
- 初期纯数值升级目标回本30–120秒；初级自动化可接受2–5分钟，因为还释放操作；后期再渐增。
- `ΔR_net<=0`时不写虚假“回本”，显示资源瓶颈或能力收益。
- 不存在连续两个阶段只买同一种东西最优；也不刻意强迫平均加点。
- 同一固定种子比较：人工优先、训练优先、自动化优先；加入低正确率、慢阅读、提前花光钱、欠费、离线重进场景。
- 停电后仍可用人工回答赚到恢复供电的钱；不卖掉唯一必需显卡。
- 若超过目标时间，先调整成本/收益/门槛，不能靠隐藏补助或宣称“多等一会”糊过去。

## 10. 最小实现路线

1. 本次：0元新档 + 首个人工×2节点 + 原有状态兼容 + 单价显示 + 测试。
2. 下一次：重复加薪II–X、连击容错、便宜的run.sh；给节点增加必要的可见阶段和行动门槛，不先建通用科技树编辑器。
3. 再下一次：统一旧任务/新订单收入入口与算力消耗；随后落自动标注里程碑和服务等级。
4. 最后：后台/早停/调度的完整触发和恢复，实测三种策略的30–90分钟节奏。

复用：XgCatalog.Nodes/Research、XgSim.BuyNode/Status、S.unlocked、S.handCorrect、S.epochs、S.papers、S.best、S.contracts。首个manual_pay继续作为I级，旧存档不用改schema；如果以后采用重复节点，II–X使用稳定id而非按列表位置存档。
