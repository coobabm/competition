# 灵光一现 · 自由成长设计 v1.2（参数成长版）

日期：2026-10-07
状态：**设计稿，未实施。** 本稿按用户最新明确设定重写；替代此前同文件中的“分任务独立验收”方案。下列示例数值仅用于解释玩法，尚未做平衡验证。

## 0. 核心就这一条

> 做题增加参数量和金钱；金钱买数据和道具；参数量达到门槛，直接解锁能力。

```text
做题 ──→ 参数量增长 ──→ 达到门槛 ──→ 新能力自动解锁
  │                                      │
  └──→ 金钱 ──→ 买数据：一次增加参数       └──→ 更方便地做题和赚钱
          └──→ 买道具：持续提高收益或效率 ──────────┘
```

**不再要求玩家独立考试、过墙、调出黄金参数或完成指定阶段。**

这是“参数量变 → 能力涌现”的增量养成玩法，不是训练流程教学。参数量在本作中是可积累的游戏成长数值，不等同于本机聊天模型的实际权重数量。

## 1. 玩家只需要理解两个数

| 数值 | 怎样获得 | 用来做什么 | 会不会减少 |
|---|---|---|---|
| 参数量 | 做题、喂入购买的数据 | 直接解锁能力，显示下一能力还差多少 | 正常玩法只增不减，不当货币消费 |
| 金钱 | 做题、已经开放的自动工作 | 买数据和道具，沿用已有必要支出 | 购买或支付支出时减少 |

取消原六阶段编号，保留一条明确的“距离下一次涌现”进度条。不同题型可以自由选，不新增文字／视觉／逻辑各自的毕业考试或必修顺序。

## 2. 做题：同时拿两种奖励

本稿采用以下默认结算规则；这是设计选择，不是已经实现的行为：

- 答对：获得本题参数奖励和金钱奖励，同时飘出两项数值。
- 答错：显示正确答案和原因，不发本题奖励，也不倒扣已经积累的参数。
- 每张题卡实例只结算一次，防止重复点击、读档或重发结果重复领奖。
- 简单题一直可做。较难题可以给更高奖励，但由玩家主动选择，不按累计答题数强制升难度。
- 基础题库免费且持续供题，钱花完也能继续做题恢复。

示例，不是定稿平衡：

```text
答对一题：+100 参数，+¥1
当前参数：4,900 → 5,000
达到门槛：自动做题能力已解锁
```

连击、动画和音效沿用现有表现。连击中断只影响额外收益，不夺回已有成长。

## 3. 花钱：数据是一次补给，道具是长期投资

为保持简单，本稿默认**数据购买后直接喂入并增加参数**，不再增加必须点击的训练／考试步骤。

### 数据包

- 显示价格和明确的参数增量：例如“¥10 → +1,000 参数”。
- 确认购买后，扣钱、喂入、增加参数，再检查能力解锁。
- 喂入可以有短动画，但结算只能发生一次，跳过动画不丢奖励、不多奖励。
- 基础数据包可重复购买；重复购买就是再次获得所示参数，不要求做更多付费题才能拿到收益。
- 首版不额外加入数据噪声、清洗费用、验收失败等门槛。已有诊断内容可留在可选实验室，不影响主线成长。

### 道具

| 道具作用 | 玩家能理解的效果 | 边界 |
|---|---|---|
| 参数收益道具 | 每答对一题，多增加一些参数 | 不直接赋予某项能力，仍由参数阈值统一判定 |
| 金钱收益道具 | 每答对一题，多赚一些钱 | 不消耗参数、不要求过某一阶段 |
| 自动效率道具 | 已解锁自动做题后，处理得更快 | 自动功能不能再被道具购买二次上锁 |
| 设备道具 | 提高既有工作速度或并行能力 | 换低配设备只影响运行，不收回已解锁能力 |

示例投资选择：现在买一个数据包，立刻接近下一能力；或者买永久收益道具，让后面的每道题更值钱。价格和等级曲线后续用模拟与实玩调优，不先添加更多货币。

## 4. 能力：只检查参数阈值

### 唯一解锁规则

```text
累计参数量 >= 该能力需要的参数量
                 ↓
        立即标记解锁，永久保留
```

不附加下面这些条件：

- 必须通过某张测试卷。
- 必须使用 CNN、LSTM 或某套指定架构。
- 必须先完成某个剧情或在某个月份。
- 参数已经够了，还必须再付一笔解锁费。
- 先把文字、视觉等所有方向各完成一遍。

一次数据购买跨过多个阈值，就解锁所有已达到的能力。提示可以合并、表现可以排队，但功能不能等待动画播完才开放。读档只补齐应有功能，不重复发首达奖励或倒演旧剧情。

### 能力示例（门槛仅为演示，不是最终配置）

| 参数量示例 | 直接获得的能力 | 玩家看到的变化 |
|---|---|---|
| 1,000 | 给出答题建议 | 它开始在题旁给出自己的选择 |
| 5,000 | 自动做基础题 | 免费出现自动开关，不再要求购买脚本才能使用 |
| 20,000 | 用短句交流 | 不只是提示答案，能够用简短语句回应 |
| 100,000 | 记录并提取重要信息 | 能保存玩家交代的事，并在需要时使用 |

后续可以加入看图描述、处理长内容、并行工作等能力，门槛数量按内容需要配置，不再固定为六次突破，也不重建六阶段通关流程。

**内容选择与成长顺序分开：**玩家可以自由选题、选择买数据还是道具；能力按参数门槛逐步出现。这是用户明确选择的成长方式，不再采用上一稿的“各任务分别考试认证”。

## 5. 自动化：让成长加速，不把它变回考试

- 参数达到自动做题门槛后，功能直接可用；由玩家决定是否开启以及处理哪些已支持题型。
- 自动完成的题也按同一奖励规则增加参数和金钱。正常自动增长就是本玩法的一部分，不把它当成需要处罚的行为。
- 自动结果不能为了保底收入把错误偷偷改成正确；错误不发报酬。自动表现可以由游戏能力配置和现有判断机制决定，不宣称等同真实训练部署。
- 自动做题不享受“手动连击”奖励，让玩家想加快时仍有参与价值。
- 同一工作不能既结算逐题收入，又额外按重复来源结算一遍收入。
- 资源不足时只暂停或减慢运行，能力保持解锁；基础人工题不受此影响。
- 离线收益沿用有上限的已有机制，只计算一次已覆盖时段，不新建无限离线加速系统。

普通订单若继续保留，应按对应参数能力提供入口和可预测收益，不能再把独立考试分数作为第二道能力门槛。工作内容、接受状态和实际执行仍需有记录；“能力已解锁”不能冒充“订单已经完成”。

## 6. 涌现：数值到点，马上看到它变了

每个重要解锁都给一个短小、能立即体验的表现：

- 答题建议：它第一次抢在玩家点击前给出提示。
- 自动做题：玩家停手，一道题被处理，两种奖励进入账本。
- 短句交流：它第一次完整回应玩家，而不是弹出一张能力说明卡。
- 记忆功能：它保存一件玩家确实说过的事；之后真正检索到时才说“我记得”。

**能力的获得靠参数，能力的表现靠实际功能。**

不让剧情或考试阻止解锁，但也不让阈值替系统编造已经发生的事情：

- 可以解锁记忆，不能凭空制造共同回忆。
- 可以解锁并行工作，不能声称已经完成三份未执行的任务。
- 可以解锁表达形式，不能把固定展示说成现场验证出的通用智能。

保留最新“私人拥有 AI”的时代优势叙事。专家检验是可选剧情，检验结果仍需要新题回执；不再用它批准普通能力。交付、发消息、接新单和公开技术仍由玩家确认。

## 7. 界面只突出做题与下一次涌现

```text
参数量  4,900                 金钱  ¥18
下一能力：自动做题            还差 100 参数
███████████████████░

                当前题目
             [ 是 ]  [ 否 ]

本题奖励：+100 参数  +¥1

[数据商店]   [道具商店]   [已解锁能力]
```

- 主操作是做题，不再把“教／考／部署”做成三道必经流程。
- 数据和道具复用现有商店与卡片，不替换 DreamOS 桌面。
- 学习率、准确率、概念盘等旧内容降为可选详细信息或实验，不占主循环，也不重新限制参数成长。
- 到点先更新能力，再播放轻量涌现效果；跳过效果仍能立即使用。

## 8. 保留与废止的边界

### 继续保留

- 2016 私人电脑、原生桌面、人物、共同经历、SI 暗线和既有关机选择。
- 现有已确认的内容删减，不恢复巨信、SLA 高价单、退役合同与退役付费题桌。
- 玩家对外发送、提交交付、接单和进入终局的确认权。
- 原有关系数值和真实聊天记录，不用金钱或参数直接虚构亲密程度。

### 按用户最新设定废止

- 上一稿的分任务独立考试资格、质量认证解锁与试训先行要求。
- 六阶段先后顺序、黄金参数过墙、指定架构毕业与强制多领域通关。
- 参数达标后再付费、再过剧情或再考试的二次门槛。

日期与能力解耦，2016 年日期不再由六阶段编号决定。日历只服务时代内容，不阻止能力开放；终局仍由玩家选择，不因后台参数增长自动关掉游戏。

终局邀请可以挂在一个明确的末端参数里程碑上，而不是六阶段终测。到点开放入口、允许继续培养；进入后仍保留信件和关机抉择，不新增毕业考试，也不让可选专家线成为必修。具体门槛随整体时长调优。

## 9. 最小工程交接

本轮只改设计，不改下面的代码。

1. **明确成长参数的来源。** 当前 `XgSim.ParamsK` 是架构／层宽对应的模型规模估算，并用于显存计算，不能直接当成答题累计值。复用存档约定增加唯一的累计成长参数字段；实现名称在编码计划中确定。对玩家主界面只显示一个成长参数量，内部资源计算与它分开。
2. **统一奖励入口。** 人工题和自动题共用一次性结算路径；每次结算更新金钱、成长参数，再检查全部能力阈值。
3. **统一解锁入口。** 能力表只包含能力 ID 和所需参数等必要配置；旧阶段、考试、架构门槛不能继续在 UI、后台或存档修复里挡住已解锁能力。
4. **复用商店。** 数据包处理一次性参数增量，道具处理明确的持续收益；购买与扣款／发放一起完成，失败不产生半笔交易。
5. **保留已有可用功能。** 已拥有的能力不因设备变化或旧档换算被收回。旧档只做一次版本化换算：至少达到已拥有能力所需的最高阈值，并保留钱包、物品和真实剧情记录；不从历史答题累计重复领取金钱。
6. **参数功能与剧情事实分开。** 达标就授予能力；事件仅记录实际使用结果。保留送达、只触发一次和退出恢复机制。

已有代码落点：

- `Assets/LingGuangV05/XingGuang/Core/XgSim.cs`：规模估算与人工题结算。
- `Assets/LingGuangV05/XingGuang/Core/XgModels.cs`：存档及模型记录。
- `Assets/LingGuangV05/XingGuang/Core/XgSim.Collaboration.cs`：自动题结算与已有收益道具。
- `Assets/LingGuangV05/XingGuang/Core/XgSim.Progression.cs`、`XgCatalog.cs`：现有阶段权限与目录。
- 现有数据商店、道具界面、Story Bridge 和能力消费者：移除与最新解锁规则冲突的二次门槛。

不需要先重写真实训练器、建立独立验收系统或新增 LLM 服务。旧概念盘可以留作表现／可选实验，但不能反过来否定已经达到参数门槛的能力。

## 10. 验收

以下为后续实现要求，本轮未运行：

- [ ] 正确做题一次，同时增加应得参数和金钱；重复提交不重复结算。
- [ ] 答错不倒扣成长，零资金仍能继续做基础题。
- [ ] 数据购买按明示增量结算；永久道具按明示范围持续生效。
- [ ] 参数达标立即解锁，不检查阶段、独立考试、指定架构或额外解锁费。
- [ ] 单次增长跨多个阈值全部解锁；跳过动画、重启读档均不丢能力或重复领奖。
- [ ] 自动做题产生参数与金钱，但同一工作来源不重复结算。
- [ ] 设备降级／停电不收回能力；恢复后可继续运行。
- [ ] 旧档换算一次且不倒扣资产，不重复发钱，不凭参数补造历史工作或聊天。
- [ ] 已退役内容不恢复，最新剧情的真实交付与玩家确认边界保留。

**最小可玩版本：一种题目 + 两种奖励 + 一种数据包 + 两种收益道具 + 两个参数能力节点。先验证这条循环是否有趣，再扩展题目、道具和能力。**
