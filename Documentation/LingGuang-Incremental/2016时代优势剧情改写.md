# 2016 年：私人拥有顶级 AI 的时代优势

## 已落地的叙事目标

不是让群友轮番宣布“你造出了未来”，而是让玩家逐渐发现：以前需要自己守着的工作在继续；别人开始认真把事情交给自己；最后，自己可以不立刻答应。

情绪顺序：**怀疑脚本 → 真实救场 → 一个人像团队 → 临时换题仍完成 → 没说完便接住上下文 → 被认真检验 → 拥有选择权。**

这里的优势来自同一台私人电脑上逐渐养成的能力、真实工作记录和玩家掌握的最后确认权，不是把普通翻译说成 2016 年全世界都做不到。保留训练、改错、架构突破与关机终局。

- 当下研究生使用 `zhou_now`。本资源没有任何让未来老周主动联系、泄露未来或知晓玩家尚未做过之事的台词。
- 灵光使用已有 `lingguang`，仍会承认“不确定”，仍把发送、回复、检验和接单的决定交还玩家。

## 分支与旧档

1. 早期怀疑、救场、并行有明确阶段窗口。高阶段旧档不会倒演第一次自动工作，也不会因补剧情而编造历史成果。
2. 并行场景直接依赖当前可核查的工作状态，不强依赖旧档可能错过的阶段 2 对话。
3. 交付链从当前翻译能力开始，沿“前导 → 接批说明 → 初稿就绪 → 确认交付 → 身份回复 → 上下文选择”串联。
4. 专家线可由当前能力直接主动发起，不要求玩家为了见研究生重演全部早期社交事件。
5. `fired.<id>` 在现有引擎中代表事件完成后才成立；所有新 `say` 后紧接 `waitSignal`，避免聊天尚未送达就推进其后续。
6. 既有投稿退回、关机问题及是/否结局未改。新拥有感场景不以奖励为名自动替玩家投稿、暴露结构或做新的外部决定。

## 实际接入约束（实现更新）

- 亲友委托不依赖被并行移除的众包/巨信；本体通过接线的「亲友委托 · 商品文案交付」执行。断线、停电、能力不够都会停住。
- 文件中的20份商品文案为游戏内预先编写的委托样例，按真实资源门禁逐份产出，并非调用真实大模型或写出宿主机文件。两条歧义留在单独清单，须玩家确认才交付。
- 专家验收不是普通评分的85%：翻译的普通分数有缩放上限。现在使用当前训练概念权重快照判读20道独立新题、正负各10，使用原始正确率；排除训练、诊断、既有考试和已用验收签名。题目不足不拿旧题凑数。
- 专家只验翻译；现场检验锁定请求时选择的数据集。不同数据集的旧高分不能冒充验收。参数/题目/预测/真值与seed保存在回执。当前训练快照不是任意历史检查点重放。
- 「去训练调整」只切到相应训练界面，不擅自重置训练步数、改变数据集或替玩家训练。
- 玩家明确选择终局不被强制阻拦；只延后自动的旧终局消息。终局一旦开始，委托处理、文件夹和新社会消息全部安静退出。
